# 本地后台生命周期

桌面端和 CLI 共用 `miniq-local::lifecycle`。这是普通用户进程管理，不安装系统服务，也不需要辅助功能或屏幕录制权限。

## 身份与锁

`daemon.json` 必须包含端口、认证 token、PID 和平台进程身份。Windows 使用进程创建时间；Linux 使用启动会话 ID 和进程启动 ticks；macOS 使用启动会话 UUID、进程唯一 ID 和启动时间。PID 存活不等于身份匹配。查询权限失败会返回错误，不能当作进程不存在。

Windows 查询只申请查询和等待权限；强制退出时另开终止句柄并重新核对身份。Linux 使用 pidfd 发送信号，要求内核支持 pidfd（Linux 5.3+）。macOS 在发送信号前再次核对原生身份；其 PID 信号接口仍存在检查与发信号之间的极短竞争窗口，不应声称与 Windows 句柄或 Linux pidfd 一样具有原子保证。

`daemon.lock` 由后台进程持有整个生命期；`daemon-lifecycle.lock` 串行化客户端的启动、停止与更新。桌面更新从准备阶段到安装完成或取消持有操作锁；CLI 激活更新从检查运行中后台到新后台就绪持有操作锁。任务繁忙时，更新仍遵守原有的空闲关闭策略，不会自动强杀任务。

## 启动与停止

- 就绪必须通过带 token 的 WebSocket `daemon.health`，并核对协议版本和服务版本字段；HTTP 200 不足以证明就绪。
- 启动保留子进程对象，同时检查退出状态。立即退出会报告退出状态和完整 stderr 日志路径，不再空等 90 秒。
- 启动超时保留仍运行的后台，避免误杀长时间初始化的进程。用户退出应用时取消本次启动，并终止、回收自己刚创建的子进程。
- 明确退出时，即使关闭 RPC 失败，也会等待宽限期，再对身份确认的进程执行强制退出。身份缺失、不匹配或无法查询时不按 PID 强杀。
- Unix 子进程使用独立 session。Windows 隐藏控制台并在宿主 Job 允许时脱离 Job；不允许脱离时保留启动能力，并在启动日志说明后台寿命仍受宿主约束。

启动 stderr 在数据目录 `logs/daemon-start-*.log`，记录启动程序路径和客户端版本；正常运行日志继续使用 `logs/daemon.log.*`。不把含 token 的连接 URL 放入错误信息。

## 新连接格式

不兼容缺少进程身份的旧连接记录。无后台持有 `daemon.lock` 时，启动会清除无效记录并重建；旧后台仍在运行时会报错，需先用旧客户端正常退出后台，再启动新版本。不要手动修改 PID/身份字段，也不要按旧 PID 结束进程。

## 验证

`cargo test -p miniq-local` 使用临时目录和独立子进程覆盖 PID 身份不匹配、立即退出、关闭 RPC 失败、取消、超时保留、认证与协议拒绝、跨进程操作锁及并发启动。Windows 另有真实 DACL 测试，验证没有终止权限时仍能观察进程、终止失败仍上报权限错误。

`.github/workflows/daemon-lifecycle.yml` 在 Windows、macOS 和 Linux 上运行相关测试，不构建或发布安装包。本地跨目标 `cargo check` 只证明编译通过，不能替代原生故障测试。
