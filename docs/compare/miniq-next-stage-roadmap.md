# miniQ 与 ChatGPT 桌面客户端全面对标及下一阶段演进路线图

> **2026-09-23 更新**：当前结论见 [2026-09-23 重新对比](2026-09-23-recompare.md)。下面的矩阵按 `v0.1.41` 写成；2026-09-22 那份按 `0.1.48` 写成。两份都只作历史记录。

> **分析基准**：
> - 对标对象：本机实测运行的 `/Applications/ChatGPT.app`（版本 `26.901.51231`，内部代号 Codex，Electron 架构，ASAR 解包分析，动态观察 `app_automation` 截图与 AX 树）。
> - 自研对象：`miniQ` 桌面端与分布式架构（Rust 多 Crate 底座 + Tauri/Web 工作台 + 移动端中继）。
> - 产出目标：全景对比矩阵、核心差距定性剖析、工程化落地的下一阶段演进目标与实施路线图。

## 一、全面对比分析矩阵

| 对比维度 | ChatGPT 桌面端 (Codex 架构) | miniQ 现状 (v0.1.41) | 差距评级 | 核心原因与体验差异 |
| :--- | :--- | :--- | :---: | :--- |
| **整体视窗布局** | 弹性三栏式：左侧会话/项目树 + 中间流式执行流 + 右侧多标签工作台（支持拖拽、全屏、终端联动）。 | 类似三栏式：左侧侧边栏 + 中间对话区 + 右侧 Workbench（支持浏览器、文件、Diff）。 | 良好 (已平齐 85%) | miniQ 已补齐侧边面板，但在多面板内容联动、跨面板拖拽细节上略有差距。 |
| **设置体系 (Settings)** | 分设「个人」、「集成」、「编码」、「已归档」4 大分类共 17 个子页面，粒度极细（如防休眠、外部编辑器绑定、队列模式、三级通知等）。 | 设置分散在独立抽屉与对话框中，偏向基础配置（模型、API Key、基础开关）。 | **显著差距** | 缺乏针对 macOS 长任务电源管理、外部 IDE 联动、全局唤醒等专业桌面级体验设置。 |
| **长任务输入流 (Composer)** | **跟进队列机制 (Follow-up Queue)**：执行耗时任务时，用户输入可选择「加入队列 (Queue)」或「调整方向 (Steer)」，带可视化消息排队托盘。 | 任务运行时多为单向锁定或粗暴打断，缺乏待办消息排队、动态调序交互。 | **核心差距** | 用户在 Agent 长程思考时无法顺畅输入后续诉求，心智负担重。 |
| **多智能体前台可视化** | **Sub-agent 头像堆叠 + 进度 Badge**（如 `子智能体 72 完成`），点击可展开子 Agent 独立时间线与产物。 | 后台有强大的 `agent_run` 并发调度与输出收集，但前端呈现较为平铺，缺乏紧凑生动的状态收敛动效。 | **中度差距** | 缺乏视觉化层次感，无法给用户直观的「团队作战」协同感。 |
| **外部编辑器联动** | 设置中可指定 VS Code / Cursor / 系统默认，代码块与 Git Diff 界面自带一键跳转外部 IDE 按钮。 | 主要在内置的 Monaco/Preview 中展示，缺乏无缝一键调起外部 IDE 并定位到特定行号的能力。 | **显著差距** | 严肃开发者日常深度依赖 VS Code / Cursor，内置编辑器无法替代完整插件生态。 |
| **系统级防休眠 (Keep Awake)** | 提供「运行时防止系统休眠」开关，长程任务自动调用 macOS `IOPMAssertion` 阻止睡眠。 | 纯依赖 macOS 默认调度，长时间网络调研或批量任务易受系统合盖/休眠影响而中断。 | **关键细节** | 影响 Agent 离席长任务的交付可靠性。 |
| **自动化任务中心 (Automations)** | 拥有系统一级「已安排的任务」主面板，支持模板库克隆、Cron 周期调度、执行历史与成果归档。 | 具备底层任务与脚本调度能力，但缺少可视化的一级页面看板供用户直观管理自动化任务。 | **核心差距** | 用户感知不到定时自动化价值，无法像日程管理一样排布周期性 Agent。 |
| **日常 Chrome 宿主复用** | 配备专用 `chrome` 原生通信扩展，可直接复用用户已登录日常 Chrome 窗口的 Cookie 与会话。 | 依赖内嵌的独立沙箱浏览器（Isolated Browser），遇到复杂登录与两步验证必须重新登录。 | **中度差距** | 无法借力用户已有的企业 SSO / 内部站点登录态。 |
| **Office 产物专业审美** | Primary Runtime 内置完整的 Office 插件体系（`documents`, `spreadsheets`, `presentations`），带严格版式与配色规约。 | `miniq-docs` 偏向基础格式转换，缺乏深度的排版美学与母版控制，生成复杂 PPTX/Excel 时不够精致。 | **中度差距** | 生成文档往往需要用户二次美化，难以直接用于正式商务汇报。 |
| **长效记忆可视化管理** | 独立 SQLite（`memories_1.sqlite`），并在设置里提供用户可见、可检索、可删除的事实记忆列表。 | `miniq-memory` 具备检索与存储 API，但界面上尚无专用的可视化「记忆与偏好」管理看板。 | **体验差距** | 用户不知道 AI 记住了什么，无法修正误记的事实。 |
| **计算机操控 (Computer Use)** | 具备后台无感辅助功能（`app_automation`）与前台键鼠接管双通道，支持沙箱与权限审批。 | 架构已完全拉齐：原生实现后台 AX 控件操控与前台桌面截图接管，且通过生产级审计。 | **完全拉齐** | miniQ 在后台无干扰操控（AX 树）上甚至更具本土可控性。 |

## 二、下一阶段四大演进目标（Goals）

基于上述对标差距，miniQ 下一阶段应围绕**「桌面级体验深化」、「长任务人机交互」、「高价值办公落地」**与**「无缝生态借力」**四大目标攻坚：

### 目标 1：打磨极致丝滑的桌面级长任务交互（桌面原生化）
- 引入 **Follow-up 消息排队与重定向机制**，让用户在 Agent 深度推理期间随时补充灵感、排布待办或矫正航向。
- 引入 **macOS 电源管理与后台驻留**，保证长时间自主任务合盖不中断。
- 完善 **外部 IDE（VS Code / Cursor）一键穿透跳转**。

### 目标 2：重塑多智能体（Multi-agent）的前端表现力
- 在中间对话流实现 **Sub-agent 聚合卡片**：多智能体并行时，展示堆叠头像、当前状态动效、聚合进度徽章（如 `3 个子任务运行中 · 18 步已完成`）。
- 支持分层折叠与展开钻取：用户既能看全局进展，又能随时点开任意子任务查看独立时间线。

### 目标 3：升级自动化与办公生产力交付体系
- 在桌面端打造系统一级的 **「已安排的任务（Automations）」看板**，让定时任务、周期性报告生成变成可视化卡片。
- 为 `miniq-docs` 注入 **专业排版审美规则库**（借鉴 Word/PPTX/Excel 专家规范），生成即是高质量商务交付物。

### 目标 4：打通用户日常浏览器生态
- 开发配套的轻量 Chrome Native Messaging 插件，支持安全读取用户授权的日常 Chrome 标签页，彻底解决复杂业务系统的二次登录痛点。

## 三、工程落地与实施路线图（Roadmap）

### 第一阶段（Phase 1）：交互质感与长任务底座（建议周期：2-3 周）

1. **Composer 待办消息队列与 Steer 交互**：
   - 在前端输入框增加「排队模式」状态条；当检测到当前会话正处于执行态时，输入框支持快捷键切换：
     - `Enter`：加入待办队列（显示排队气泡，按顺序排队）。
     - `⌘+Enter` 或右侧切换按钮：立即重定向（Steer 中断重导）。
   - 用户可随时在队列列表中拖拽调整顺序、编辑或删除排队消息。
2. **macOS 运行时防休眠（Keep-Awake）**：
   - 在 `miniq-daemon` 中增加 macOS 原生电源控制绑定（调用 `IOPMAssertionCreateWithName(kIOPMAssertionTypePreventUserIdleSystemSleep)`）。
   - 在设置中暴露「长时间运行防止系统休眠」开关，任务开始时激活断言，任务完成或中断时自动释放。
3. **外部 IDE 深度联动**：
   - 设置项新增「默认文件打开方式」：支持自动探测本地已安装的 VS Code、Cursor、Zed、系统默认应用。
   - 所有生成的文件卡片、代码块头部、Git Diff 查看器右上角增加「在外部编辑器中打开」图标，点击通过系统 URI scheme（如 `vscode://file/{path}:{line}`）精确跳转到对应行。
4. **Token 上下文用量与耗时指示器**：
   - 对话流顶部/输入框边缘增加 Context Window 消耗进度条（例如 `已消耗 45k / 128k (35%)`）。
   - 任务运行条增加动态耗时计时器（`已处理 X分Y秒`），增强长任务等待掌控感。

---

### 第二阶段（Phase 2）：多 Agent 视觉收敛与记忆看板（建议周期：3-4 周）

1. **子智能体前台可视化呈现**：
   - 设计 `SubAgentStack` 组件：将 `agent_run` 启动的子任务在父任务时间线上收敛为一个微型看板（堆叠头像、动态脉冲、完成度 Badge）。
   - 点击展开抽屉式侧面板或内联折叠区域，查看每个子 Agent 的输入参数、实时思考流与输出成果。
2. **长效记忆（Memories）与个人偏好可视化管理**：
   - 在设置面板中增加独立的「记忆与偏好」管理视图。
   - 分类展示：用户工作背景、编码偏好、常用技术栈、自定义要求。
   - 支持用户手动添加事实记忆、编辑现有记忆、一键清空或删除某条误记记忆。
3. **设置面板重构与全局悬浮窗（Popover）**：
   - 将现有零散抽屉统一重构为多模块系统设置窗（「个人」、「自动化」、「工具与集成」、「开发者」）。
   - 支持全局快捷键（如 `⌥+Space`）调起 miniQ 快速提问悬浮小窗，随叫随到。

---

### 第三阶段（Phase 3）：自动化中心与专业 Office 体系（建议周期：4-6 周）

1. **可视化「已安排的任务（Automations）」主视图**：
   - 在主界面左侧导航栏增加一级入口「自动化任务」。
   - 提供开箱即用模板库（例如「每日竞品跟踪」、「本地代码库日常自检」、「定时生成晨报」）。
   - 包含可视化的 Cron 触发器配置器（每天/每小时/工作日）、任务历史运行记录、产物直达链接。
2. **Office 交付物审美规范库**：
   - 参考 Codex 运行时插件设计，在 `miniq-docs` 上层引入模板与排版指导规范：
     - **Word**：注入标准正规公文/咨询报告样式（统一标准色系、层级标题间距、标准三线表、专业页眉页脚）。
     - **PPTX**：预设 4 套现代化商务幻灯片母版（科技蓝、雅致白、深邃黑、商务灰），卡片化排版，避免文字堆砌。
     - **Excel**：自动应用财务标准格式（货币千分位、表头填充色、公式求和与重要指标高亮）。
3. **日常 Chrome 宿主免登通信桥**：
   - 封装标准 Chrome Extension 与 Native Messaging Host。
   - 用户授权后，miniQ 可直接向已打开的 Chrome 标签页查询 DOM、提取内容，无缝复用内部系统的登录态。

## 四、总结与验收指标

通过本演进路线图的实施，miniQ 将从一个「能力强大的极客 AI 终端」蜕变为一个**「兼具桌面级原生交互美学、多 Agent 团队作战掌控力与企业级办公交付能力」**的全功能 AI 协同工作台。

- **阶段验收衡量指标**：
  1. **长任务交互满意度**：排队（Queue）与重定向（Steer）机制落地，长程任务无输入焦虑。
  2. **任务完成可靠度**：macOS 防休眠机制保证 30 分钟以上批量长任务零因睡眠断流。
  3. **专业开发者体验**：代码与变更一键唤起 VS Code/Cursor 定位率 100%。
  4. **办公审美跃升**：文档/PPTX/Excel 产物从「纯文本草稿」跃升为「开箱即用的商务格式」。
