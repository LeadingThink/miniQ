## redo 的后端改动

原撤销会删除消息，无法通过重发提示实现真正 redo。本次新增 `0030_session_redo.sql`、memory 快照存储及 daemon 的 `session.redo`：

- 保存并恢复消息、工具、审批、检查点、附件记录、上下文、计划、队列和执行计时，保留原 ID，不调用模型或重新执行工具。
- 保存撤销前后文件副本；恢复前验证会话和文件仍与撤销后状态一致，拒绝覆盖新工作。恢复失败时尝试回滚文件，并报告回滚错误。
- 未完成文件恢复的快照不能 redo；撤销已完成但 redo 准备失败时，明确报告 `redoAvailable: false`。
- 新增 `session_restored` 事件；终端、桌面与指定远程主机重新获取快照。事件日志不会用增量事件冒充完整恢复。
- 多次撤销支持依次重做；文件备份和持久化快照保存在 daemon 数据目录。本轮没有新增历史备份自动清理策略。

- Windows 本地 CLI 二进制测试：176 通过，1 个需要真实交互终端的手工 fixture 按原设置忽略。
- 终端生产渲染器测试：17 通过；导出并查看模型加载/错误、队列动作、浅色多选、深浅色图片预览等实际帧。图片位于忽略目录 `.miniq-audit/terminal-parity`，未加入版本控制。
- daemon redo/恢复事件测试 4 通过；原有消息重写相关测试 5 通过。memory redo 持久化测试 3 通过，原有撤销/重写集成测试 2 通过；远程方法分级测试 12 通过。
- 桌面相关 5 个测试文件共 71 项通过（前轮验证）；本轮补充的 RPC 传输测试文件 31 项通过，确认 redo 不会通过对象传输回退重试；最新 TypeScript 类型检查通过。
- `cargo check --locked -p miniq-cli -p miniq-daemon --quiet`、`cargo fmt --all -- --check`、`git diff --check` 通过。这些验证完成于版本更新前；CLI 增加对既有 image/windows-sys 包的依赖。发布准备仅做版本、锁文件及轻量检查，完整编译与验证交由 GitHub Actions。
- 后台 RPC 的手工 TUI fixture 已更新为多连接共享状态、广播事件，以适配新的异步执行方式。
- 草稿是本次终端进程中的会话级保存，不是跨重启草稿持久化；系统剪贴板依赖相应平台工具和权限，OSC 52 复制取决于终端许可。
- 图片预览为终端彩色半块缩略图；动画图片只预览首帧，附件原件不变。审批/问答遵循 miniQ 已有协议，没有虚构 OpenCode 专属的多问题批处理协议。
- `/remote` 交互设置和外部编辑器仍会主动暂时交出终端。原始行模式不提供全屏面板。
- 未完成 macOS/Linux 真实终端的逐页手工验收，也未声称与 OpenCode 像素完全一致。后续发布请求已授权同步远端、提交以及通过既有工作流发布 Windows/macOS/Linux/Android；不包含 iOS 发布。
