# miniQ 体验与 Computer Use 优化验收

基线：`a13263c`（0.1.17 后的 main）。本轮只修改、测试、提交和合并，
不发布版本、不安装、不重启正在运行的 miniQ，也不使用生产会话进行写入测试。

## 对比依据

- OpenAI Computer Use 官方页面：https://learn.chatgpt.com/docs/computer-use
  系统的屏幕录制、辅助功能权限与应用内部审批是两层不同的权限；允许用户撤销和接管，
  不代表模型能够自行批准系统授权。视觉操作必须有观察和操作后验证。
- 本机 Claude Code 2.1.234 的 `claude --help`：可核实会话模型/effort、恢复/分支、
  additional directories、后台 agent、流式子任务输出、权限模式、浏览器集成和安全模式。
- 既有 miniQ 源码、单元测试与隔离测试实例。miniQ 已有真实桌面输入、截图回传、
  120 秒独占租约和会话隔离 Chrome，不将这些既有功能重复计为本次新增。
- 尝试读取本机 Codex 原生窗口（`com.openai.codex`）时被 Computer Use 安全策略拒绝。
  本轮不绕过，不声称读取了 ChatGPT/Codex 的闭源实现；ChatGPT 对比依据为上述官方文档，
  也不宣称 miniQ 的通用任务成功率已超过竞品。

关键差距：状态和恢复入口不完整、主输出缺少稳定的执行摘要、长执行组难以定位当前步骤、
子任务结果缺少可控刷新、预览工作台切会话丢状态，以及网页模式的前进后退实际没有作用。

## 使用与边界

从 `apps/desktop` 运行 `npm run dev -- --host 127.0.0.1 --port 1478`，
打开 `http://127.0.0.1:1478/experience-hardening-preview.html`。
隔离页只在开发模式渲染，不是生产入口；模拟授权操作不会请求真实系统权限。

真实授权、原生网页弹窗叠层和真实鼠标键盘任务仍需在用户结束当前任务后，
用新编译客户端做人工验收。本轮不以假桌面测试代替真实任务成功率。
PDF 检索依赖文档文本层，不包含扫描件 OCR。Wayland 原生输入仍不支持；
单独的浏览器自动化仍可使用。B05/B07/B16/B17/B18 是下一阶段设计，不声称已经实现。

本轮不调整版本号、不打 tag、不触发发行 workflow、不安装或重启运行中的 miniQ。
原工作目录中既有未提交修改和素材保持不动；是否迁移这些内容需要用户确认。
