# miniQ 设计基线：从 Apple 设计原则到可验证的办公协作

## 范围、依据与使用方式

miniQ 的定位是面向通用办公场景的桌面 AI Coworker：用户表达目标，Agent 规划、读取资料、执行工具并交付可用结果；关键操作保留用户决定权。桌面、移动与终端应围绕同一任务与工作区协作，而不是让用户管理 Agent 的内部机制。

本基线依据通用公开设计知识、Apple Human Interface Guidelines（HIG）的公开主题，以及本次只读查看的 miniQ 产品和交互文档。下列九类原则是面向 miniQ 的归纳，不声称它们是 Apple 官方逐字列出的九条原则，也不包含创始人意图、设计起源或历史因果断言。验收阈值是本基线提出的 miniQ 工程标准，不是 Apple 官方产品承诺。

Apple 的可借鉴价值在于让人理解、操控、信任产品。圆角、渐变、半透明、动画与图标只在帮助内容辨认和操作时采用；视觉相似不能证明体验达标。

“当前落点”表示在仓库文档中找到的能力和可承接这些规则的界面。历史验收记录不等于当前安装包通过验收。本次没有运行产品、检查截图、执行测试或修改仓库；所有标准均须对指定候选版本重新验证。

## 1. 尊重人：保护时间、注意力和决定权

**用户承诺**：你提出目标后，可以继续自己的工作；需要你做决定时，我们说明缘由、影响与选择，保留你的输入和拒绝权。

**界面/交互规则**：

- 询问只针对缺少的决定或授权；已确认的选择在适用范围内沿用。一次问题给出最终措辞，不展示模型草稿、重复选项或无意义的确认。
- 审批显示将改变什么、目标对象、授权范围与有效期。拒绝和取消明确可见；不通过强调色、默认勾选或模糊文案诱导扩大权限。
- 自治任务持续可停止、可追加指令。需要前台接管时先说明；具备应用定向控制能力时优先减少光标、焦点与剪贴板干扰。
- 失败保留正文、附件和已完成成果；人在阅读历史或编辑时，不自动抢滚动或覆盖输入。

**miniQ 当前落点**：目标驱动任务、QuestionCard、审批模式与审批收件箱；问答文档记录了结构化选择、失败保留答案与防重复提交；macOS 应用定向控制文档记录了后台 AX 操作与接管边界；移动体验文档记录了阅读时不抢滚动。[M1–M4]

**可验证验收标准**：

1. 用一个包含澄清、审批、拒绝及网络失败的完整任务验证：同一有效授权不重复询问；拒绝后不执行对应动作；失败后草稿和附件仍完整可重试。
2. 任务运行时上滑阅读并编辑草稿，持续新增消息不能改变阅读位置或草稿；回到最新内容由用户主动触发。
3. 对支持后台控制的合成应用任务，前台应用、全局光标与剪贴板不因 miniQ 控制改变；需要前台接管的路径出现明确提示。

## 2. 直接操作：让对象和结果成为工作的入口

**用户承诺**：你看到的文件、计划、网页记录和产物可以直接查看与操作，不必反复用自然语言描述界面动作。

**界面/交互规则**：

- 在对象附近提供预览、打开、复制、下载、重试等相关动作；标签、分栏、页码与缩放使用稳定且可预测的行为。
- 选中内容继续提问时，展示引用对象及选区；先进入可编辑草稿，再由用户发送。
- 修改文件、重跑任务和恢复 checkpoint 均标明作用对象及覆盖范围。能预览变更的操作提供预览；不可逆动作执行前说明后果。
- 拖动、手势与悬停提供便捷路径，同时保留可发现的按钮或键盘操作。可撤销能力按真实支持范围展示。

**miniQ 当前落点**：项目文件直接预览、FilePreviewPanel、PreviewTabs、文档页码与展开分栏；移动网页记录支持带标题和链接继续提问；工具写入 checkpoint 是恢复能力的落点，但不能推定邮件发送、外部 API 等副作用也可回滚。[M1、M4、M5]

**可验证验收标准**：

1. 无需模型请求即可从项目打开文件、切换标签、跳页、缩放和恢复分栏；对象名称及完整路径可以查明。
2. 同名不同目录文件可以区分；选择一个对象执行操作不会作用于另一个对象或会话。
3. 对实际支持回滚的文件修改，预览恢复范围后执行，内容恢复到选定 checkpoint；对不支持撤销的外部副作用，界面不会提供虚假的回滚承诺。

## 3. 清晰层级：先回答“现在怎样、我要做什么、结果在哪里”

**用户承诺**：你能迅速辨认当前项目和会话、任务状态、待办决定与最终交付，不需要逐条阅读工具日志。

**界面/交互规则**：

- 项目/会话是工作归属；主答案和交付是阅读主线；计划是进度；工具与诊断是证据。用位置、标题、留白和文字层级表达关系。
- 待审批、待回答、失败与完成状态用文字和语义图标表达，颜色仅作辅助。
- 每个局部区域有明确主动作；发送与停止随真实运行状态切换，不能只靠相同图标的颜色变化。
- 空态、无搜索结果、未选择会话、离线和加载中分别表述，不把它们都显示为“暂无内容”。

**miniQ 当前落点**：时间线、计划、产物预览、执行摘要、审批收件箱、项目导航与远程连接状态；历史优化文档记录了工具分组、筛选和失败/审批展开。[M1、M4、M6]

**可验证验收标准**：

1. 用至少 5 名目标用户检查包含长任务的页面；至少 4 人在 10 秒内指出当前会话、任务状态、是否需要本人操作及交付入口。此阈值作为本项目可用性目标。
2. 在浅色、深色及灰度下检查运行、成功、失败、待审批，均能凭文字或图标区分。
3. 使用筛选和搜索隐藏普通过程后，待审批和待回答仍可发现并可处理。

## 4. 渐进披露：按问题展开复杂度，保留完整证据

**用户承诺**：首次使用能完成工作；当你需要查原因或审查动作时，完整细节就在相应位置。

**界面/交互规则**：

- 默认显示目标、状态摘要、当前步骤与结果；工具参数、原始 JSON、日志、模型协议和性能诊断按需展开。
- 披露入口以用户问题命名，例如“查看执行详情”，不要要求先理解内部事件名。
- 风险、影响对象、失败原因与下一步不能被折叠在“高级”区域内。
- 用分组、分页、搜索与延迟加载降低负担；折叠和分页不能删除或截断底层记录。专家设置应可检索、可回到原位。

**miniQ 当前落点**：ToolGroup、ToolPayload、ModelDiagnostics，以及历史优化文档中的完整证据检查器；移动入口按需加载功能模块。[M4、M6]

**可验证验收标准**：

1. 对 100 条工具记录的任务，初始页面能直接看出结果、异常和待决定事项；无需展开普通成功记录才能批准或恢复。
2. 分页、筛选与折叠后，搜索和复制可访问完整原始输出；含长行、空值、false、0 的样例不丢失内容。
3. 审批卡片收起详情时仍显示对象、动作、范围和风险；复杂命令的完整内容可在批准前检查。

## 5. 反馈：如实表达收到、执行、确认与不确定

**用户承诺**：每次操作都有可理解的响应；我们不会把按钮被点击、请求被投递或截图出现，误报为任务成功。

**界面/交互规则**：

- 操作后立即给出按下、排队或加载反馈；完成反馈必须与结果确认绑定。运行、待审批、失败、取消、结果未知是不同状态。
- 只在具有可靠分母时显示百分比；否则显示当前阶段、已完成步骤或真实耗时，不编造进度与剩余时间。
- 错误就近解释发生在哪个对象、保留了什么以及可执行的下一步；重试保护已有成功成果，避免重复副作用。
- 手动检查即使没有新版本也给出结果；无需用户行动的后台检查保持安静。流式内容不逐 token 打断屏幕阅读器。

**miniQ 当前落点**：计划和工具状态、取消、模型重试、连接状态与更新提示；应用控制区分 actionDispatched 与后续观察失败；连续性文档要求先检查未知执行结果再重试。[M3、M4、M7]

**可验证验收标准**：

1. 在正常与慢网络下，交互应在 100ms 内呈现本地状态变化；持续超过 1 秒的操作有处理中或排队信息。这里的时间阈值是 miniQ 目标，不约束外部请求完成时间。
2. 注入投递成功但观察失败的情况，显示“结果待确认”，不能显示已完成或直接重放副作用；恢复时先核对实际结果。
3. 测试复制失败、检查更新无更新、下载失败与模型异常：均有准确结果和对应恢复入口，不能假报成功。

## 6. 连续性：保留任务意义、阅读位置和已完成工作

**用户承诺**：切换会话、设备或恢复中断后，你能从正确的位置继续，知道哪些工作已经完成、哪些状态尚未确认。

**界面/交互规则**：

- 草稿、附件、标签、阅读位置与计划按会话归属；设备切换和异步响应不能串入其他会话或电脑。
- 持久化完整任务状态与已确认工具结果；恢复后标明中断点，不自动重复未知副作用。
- 跨端保持对象名称与状态含义一致，布局适配设备；明确执行电脑、当前设备权限、在线状态及观察时间。
- 历史网页记录明确标为历史资料；手机本地打开链接不暗示共享桌面登录状态。导入外部会话保留来源身份。

**miniQ 当前落点**：会话 checkpoint、多根目录与会话 cwd、外部会话导入、预览状态；桌面/手机/终端共享后台能力，移动网页记录与连接隔离。[M1、M4、M5、M7、M8]

**可验证验收标准**：

1. A/B 会话快速切换并延迟返回文件读取、截图与网络响应，A 的内容不得进入 B；返回 A 可恢复其查看状态。
2. 在任务完成一部分后中断并重启后台：已持久化结果与计划保留，未知动作标记明确；子 Agent 的重启恢复边界按实际支持说明。
3. 桌面与手机处理同一审批，实际动作至多执行一次；离线状态和记录时间可见，历史截图不展示为实时画面。

## 7. 隐私：让数据边界可理解、权限可控制

**用户承诺**：你能知道什么数据会被读取、发给谁、保存在哪里，以及授权何时结束；“在本机执行”不会被表述成“数据永不外传”。

**界面/交互规则**：

- 在模型服务、连接器、远程同步、记忆、技能蒸馏和会话导出等入口，说明数据目的、去向与保存范围；采用最小必要权限。
- 目录访问、应用控制、屏幕捕获和网络域名分开说明。授权标签表达允许一次/会话范围，不用含糊的“始终信任”。
- Key 默认遮蔽；诊断、分享、截图和导出避免泄露秘密。导出是否包含附件、工具参数或敏感内容须可预见。
- 提供授权查看与撤销、记忆查看与删除等控制；删除本地记录和删除服务商副本的范围分别说明。无法控制外部保存时如实告知。
- 加密只解释实际覆盖链路，不扩展成“匿名”“零元数据”或全面安全保证。

**miniQ 当前落点**：工作区路径与附加目录边界、审批/审计、ComputerSettings、MemoryPanel、远程设置；远程文档记载了加密转发和原生安全存储。通用 shell 的路径检查不能等同于 OS 级沙箱。[M1、M3、M7、M8]

**可验证验收标准**：

1. 用合成文件和假 Key 检查模型、MCP、远程与导出链路：界面披露与实际数据流匹配，常规日志、错误页和共享结果无明文秘密。
2. 未授权目录、符号链接逃逸和远程扩大本地目录访问均被相应边界拒绝；撤销后下一次受保护操作需重新授权。
3. 启用远程、保存记忆或蒸馏技能前，用户能查看范围；关闭远程后不再接受该连接路径的新操作。对删除功能，验证记录真正消失及其明确承诺的范围。

## 8. 无障碍：关键工作不依赖一种感知或输入方式

**用户承诺**：使用键盘、屏幕阅读器、较大文字或减少动态效果时，你仍能完成任务并处理风险决定。

**界面/交互规则**：

- 优先使用语义化控件，提供可访问名称、角色、状态及标签关联；图标按钮、进度、错误与待审批都有文字语义。
- 全流程支持键盘；焦点顺序对应内容顺序，弹窗合理约束焦点，关闭后回到触发入口，焦点始终可见。
- 不只靠颜色、声音、悬停或拖拽表达信息和操作；手势有替代入口。
- 支持文字放大、窄屏、系统减少动态效果；流式输出采用节制的状态播报。自动化可读 AX 不等于 miniQ 自身无障碍达标。

**miniQ 当前落点**：QuestionCard 的原生单/多选、预览标签键盘行为、减少动态效果记录、移动按钮和字号适配；实际屏幕阅读器覆盖仍需重新验收。[M2、M4–M6]

**可验证验收标准**：

1. 仅用键盘和目标平台屏幕阅读器完成“选项目→附文件→发送→回答问题→审批→预览→取消”，无焦点丢失和不可退出的焦点陷阱。
2. 文字放大至 200%、320px 视口下，正文、问题、审批主动作和错误信息可访问，无重叠遮挡；表格等二维内容可在自身区域滚动。
3. 常规文字对比度至少 4.5:1，大字至少 3:1，必要控件边界及焦点标识至少 3:1；作为采用的 WCAG AA 检查指标。iOS 主要触控目标以至少 44×44pt 验收，网页对应目标以 44×44 CSS px 为本项目基线，其他平台按平台度量复核。
4. 开启减少动态效果后无非必要循环或进场动画；流式回复不逐 token 播报，问题、错误与完成可以被读出。

## 9. 克制与细节：把复杂性收进可靠的一致行为

**用户承诺**：界面安静、可预测；细微操作不会造成内容丢失、错误对象操作或阅读中断。

**界面/交互规则**：

- 每个控件都有任务理由，减少重复入口与装饰；留白和材质服务于阅读、分区与交互反馈。主题不能削弱语义状态和对比度。
- 统一同类动作的名称、位置、快捷键及反馈；“停止”“取消”“关闭”“删除”按真实语义使用。
- 优先消除输入、焦点、尺寸、滚动和异步竞态问题，再增加动效。中文输入法确认候选不等于发送。
- 页码等多位输入先编辑、再提交；长路径可辨认并可复制完整值；长历史、表格与日志按需加载但不丢数据。
- 不为装饰主动重启、打断长任务或抢焦点；性能优化以维持已有工作为前提。

**miniQ 当前落点**：原生预览文档中的页码草稿、最短可区分目录、焦点恢复、文档不重新挂载；问答和移动文档中的 IME、防重提交、懒加载与历史分页；主题系统是检验这些规则的覆盖范围。[M2、M4、M5]

**可验证验收标准**：

1. 输入中文候选、连续输入多位页码、快速切换预览、关闭标签、调整分栏后，均符合提交与焦点规则，阅读位置不无故跳动。
2. 在浅色、深色和自定义主题中检查长中文、长路径、同名文件、空值、大文件与失败样例：主动作可用，全文可访问，真实对象可识别。
3. 对连续双击、慢响应和重复点击，发送/审批只产生一次有效提交；预览扩展不因布局变化重新解析文件或丢失查看位置。
4. 审查每个新增装饰和动画能否说明其阅读或操作用途；无法说明时移除。尺寸、间距、字重和圆角用一致规则，不逐页随意堆叠。

## 评审与验收记录

每次评审记录候选版本、平台/设备、任务样例、失败注入条件与实际结果。逐项标记“通过、失败、未验证、不适用”，附证据及不适用理由；历史文档不能直接勾选为通过。优先修复误执行、权限误导、内容丢失与关键操作不可访问，再改善信息层级与视觉细节。

建议用同一条合成办公任务贯穿上述标准：读取非敏感资料，生成报告，处理一次审批，预览同名文件，模拟网络中断，在移动端继续，并检查恢复。使用独立临时工作区和假凭据；测试外部副作用以可控合成对象替代真实客户数据。
