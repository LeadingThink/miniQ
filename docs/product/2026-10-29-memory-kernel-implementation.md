# miniQ 记忆内核实施记录

日期：2026-10-29。开发分支：`codex/memory-kernel`，基线 `7cfc803`。未修改应用版本或发布配置。

## 已实现的行为

沿用 miniQ 的 Rust daemon 和 SQLite，以 MicroClaw 的分层召回为主，采用明确写入决策、来源和版本、增量任务及失效机制。没有引入独立服务、外部向量库或第二份事实存储。

- 新增、更正和后台提炼共用事务写入入口。返回 `added / updated / unchanged / needs_confirmation`。完全重复的内容不新增；同一结构化键的不同内容要求明确更正；更正使用逻辑 ID 和 `expectedRevision`，并发修改只有一个成功。
- 当前事实和历史版本分开。保存来源消息 ID、内容 SHA-256、支持证据的 UTF-8 字节区间。原有记忆完整迁移为 revision 1、来源 unknown，不推断为用户已确认。
- 每个用户轮次召回一次全局和当前项目事实；稳定偏好优先，其他内容使用 FTS5/BM25。中文使用字符和双字词索引，英文和数字使用词项。选择完整条目，保留原文；大文本可以通过精确读取取得。
- 记忆只注入当次模型请求，不写进聊天消息、压缩输入和持久化快照。记忆工具的历史结果和工具归档只留 ID/revision 引用；读取时重新校验当前版本。主会话和子代理恢复时同时校验记忆处理代次，失效后丢弃模型私有上下文；子代理的中间和最终持久化共用清理入口。带记忆的请求关闭不可检查的服务端自动压缩，继续使用客户端压缩。
- 删除同时移除事实、旧版本、来源关系和全文索引，并保存不含事实明文的排除信息。来源重放、索引重建、过期任务和迟到快照都不能恢复对应记录。原始聊天和已经发送的回复保留；明确再次要求保存可以创建新事实，旧来源仍不会自动重放。
- 来源被删除或编辑时，没有独立有效来源支持的事实失效。多个独立来源支持同一事实时，删除一个来源不会丢失其余依据。
- “继续上次”等请求提供同项目的延续索引，通过 `memory_project_read` 读取实时目标、已完成/待处理检查项、带来源的项目决定、成果文件引用、最近轮次结果和观察时间。交接摘要直接由现有状态组成，避免再维护一份会过时的模型摘要。失败或取消状态仍明确可见；个人待办和提醒继续使用真实任务机制。

## 受控自动提炼

现有记忆页面保留项目/全局、搜索、分页和删除结构，只增加两个功能开关：

1. **在聊天中使用已保存的记忆**：默认开启。关闭后自动召回和模型的记忆读取停止；用户仍可在管理页查看/删除。
2. **自动保存项目偏好和事实**：默认关闭。开关对当前连接的所有项目生效，记忆分别保存在来源项目。开启是限定的后台保存授权，使用会话当前配置的模型并产生模型用量；不扩大其他工具权限。

自动提炼只消费开启后的成功轮次中的用户来源，不复制原始聊天。失败、取消、定时任务输入、临时侧聊、分支继承内容和已导入的历史不自动成为新来源。关闭后再开启不会回扫期间的旧聊天。关闭“使用记忆”不会取消仍已授权的自动保存，两项政策相互独立。

任务、游标、处理代次和租约保存在 SQLite。每批最多 6000 个 Unicode 字符，剩余字节保留下一批；候选与游标在同一事务提交。单 worker、90 秒调用超时、120 秒租约、4096 输出 token 上限、失败退避重试（30 秒起、最多一小时）。网络和模型调用在数据库锁外。

提炼使用源会话的模型路由，不指定其他廉价模型或 provider。每次提交重新检查设置、租约、来源哈希和处理代次。`AlwaysAsk` 暂停后台处理；在调用中切换到该模式也会阻止提交。候选必须有本页可验证的原文证据。后台只新增当前项目事实，不自动覆盖旧事实、不扩大为全局记忆。

## 验证及边界

回归覆盖真实聊天入口、跨聊天/跨项目、并发更正、旧版本退出召回、多来源删除、遗忘后的索引重建和来源重放、迟到快照、租约和游标、重启续处理、关闭授权、侧聊/分支，以及中文人名、日期、金额和中英混合检索。前端覆盖开关的明确提交、保存失败、切换 daemon 和原有记忆管理行为。

已完成的验证：

| --- | --- |

| 子代理生命周期 / 主会话与检查点回归 | 29 / 11 通过 |
| 协议、模型投影、记忆工具、RPC、上下文压缩和远程权限相关测试 | 通过 |
| MemoryPanel、记忆开关、Settings 交互 | 24 通过 |
| `cargo check --workspace`、`npx tsc --noEmit` | 通过 |
| 相关 Rust crates 的 Clippy、`cargo fmt --all -- --check`、`git diff --check` | 通过；Clippy 仍报告原有非本次功能的警告 |

本机 Windows 的 debug 构建、SQLite 内存库、1 万条模拟事实、40 次召回：p50 **57.47ms**，p95 **89.84ms**。这是本地检索基线，不包括模型延迟，也不是磁盘数据库或所有硬件上的性能保证。

提炼测试使用可控模型响应；尚未取得真实模型对角色扮演、引用、敏感信息和语义冲突的准确率数据。原文证据校验能拒绝虚构证据，不能独自证明所有提炼判断都正确。自动保存因此默认关闭，自动覆盖也没有开放。遗忘排除覆盖已知来源、版本、键及内容标识，不声称能识别任何未来独立来源里的所有同义重述。

初版没有 embedding、RRF 或重排。同义表达漏召回需要用固定数据集确认后再增强。数据仍以当前 daemon 为边界；连接同一 daemon 的桌面/手机共享状态，不同电脑不因此自动同步。
