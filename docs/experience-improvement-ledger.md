# miniQ 产品比较与优化验收清单

日期：2026-09-06。基线：c116132。共 20 项大优化、50 项细节优化。

本批在独立 Git worktree 实现和测试，没有重启、停止或替换运行中的 miniQ，
没有访问生产数据库，也没有发布新版本。下表是路线图与验收记录，不表示所有规划均已完成。

## 比较结论

| 维度 | ChatGPT 客户端 / Claude Code 的可借鉴点 | miniQ 基线与优化方向 |
| --- | --- | --- |
| 会话模型 | 会话是模型选择、继续和分支的工作单位；Claude CLI 有 model、effort 参数 | 原来主要依赖全局 provider。本批增加会话独立设置，切换不影响别的会话 |
| 多模型 | 原生产品对自家模型的参数和私有续接格式更明确 | miniQ 的优势是 OneAPI 多供应商；必须依据协议和能力元数据适配，不能统一强塞参数 |
| 长任务 | 主答案、过程、计划和产物分层，按需展开证据 | 基线大量平铺工具行。本批分组、筛选、搜索、stdout 原文和完整 JSON 并存 |
| 多 agent | Claude Code 的后台任务有身份、输出、继续和停止语义 | 基线已有子 agent，但名称注册没有会话隔离。本批修正归属并加入子任务面板 |
| 计划 | 长任务应保留可恢复的进度，而不是只靠实时消息 | 基线计划在内存中。本批落库；子计划不能覆盖主计划 |
| 预览 | 产物本身可检查，编辑位置与对话上下文联动 | miniQ 已支持 PDF、Office、媒体和代码。本批增加 HTML 隔离预览和 Markdown 目录/源码定位 |
| 浏览器 | 页面身份、操作证据和用户接管要清楚 | miniQ 有内置浏览器和自动化工具，但没有完成同任务成功率、可恢复性和安全边界的对照测试，不能断言谁更强 |
| 权限 | Claude Code 的明确权限模式和计划模式可借鉴 | miniQ 已有风险评估和审批，但独立会话策略、可恢复中断、依赖安全仍需继续完善 |
| 诊断 | 实际 token 使用量应与能力上限、估算值分开 | 本批不伪造 usage；逐轮来源记录与真实 usage 诊断列为下一优先级 |

研究依据：已读取官方 OpenAI 文档、Claude Code 官方文档和本机 `claude --help`；
只读观察了运行中的 miniQ 长任务界面。当前工具不允许直接检查 ChatGPT 原生窗口，
因此没有宣称逐像素对照或读到其闭源实现。OpenAI Docs 资料促使本批采用分层展示、
会话级控制、产物检查和原生协议参数，而不是复制一个聊天外观。

## 已发现并修复的兼容性缺陷

- Chat Completions 原来丢失 DeepSeek reasoning_content；现在跨工具轮和最终回答完整续接。
- Gemini 工具调用 extra_content/google/thought_signature 现在与对应调用 ID 一起保留。
- Claude 明确 effort 使用 output_config；适用家族启用 adaptive thinking，不给旧家族乱加预算。
- DeepSeek v4 使用本身的 thinking enabled/disabled 和 effort；不套用 Claude adaptive 格式。
- 子 agent 同名注册及读取、发送、停止、恢复原来缺少会话归属隔离，现在全链路验证所有权。
- 子 agent 的任务图有独立命名空间，不再覆盖主任务计划。
- 切换会话后的旧模型加载或更新失败，不再覆盖新会话的状态。
- 沿用默认模型但单独覆盖协议时，新会话界面与后端实际配置保持一致。
- 模型目录按大小写不敏感排序、按完整 ID 去重，不合并有意区分大小写的模型 ID。
- 时间线与 Markdown 导出保留后端时间戳的亚毫秒精度，极快工具不会因 Date 毫秒取整被排到回答之后。
- 工具 stdout/stderr 原文可读，完整 JSON 仍可切换和复制。
- 公式规范化插入的行不会再造成 Markdown 源码跳转行号偏移。
- 窄屏长文件路径不再挤压产物按钮，产物区有独立滚动范围。

## 验证边界

本批优先交付 M01-M04、M06-M08、M10、M12-M13、M15-M16，共 12 个完整大项；
M09 为部分交付。剩余 7 项需要独立实现、验证后才能算完成。

- 多协议验证使用本地可控测试服务、请求体断言和真实 SSE 解码，不消耗用户模型额度。
  没有据此宣称所有 OneAPI 别名、所有厂商服务端工具或所有模型组合已在线通过。
- 已有 Responses 和 Anthropic 原生工具/签名能力继续保留；本批未降级成纯文本模拟工具。
- 原生桌面文件读取没有在用户正在运行的客户端里执行。浏览器组件测试页验证渲染、源码和沙箱；
  原生桥由构建/类型检查覆盖，安装包级验收留待允许另启测试客户端后进行。
- HTML iframe 的 sandbox 不授予 same-origin、弹窗或顶层导航权限；资源默认 CSP 拒绝联网。
  这不是操作系统级网络隔离。自包含脚本可运行，iframe 自身导航、浏览器实现差异和外部资源仍需专门安全测试。
- 子 agent 面板状态在 daemon 本次运行期间保留，尚未实现 agent 重启恢复与完整独立时间线。
- 目录针对 OneAPI 标准完整 data 列表；上游声明分页但没有适配时明确报错，不假装拿到完整目录。
- npm 完整依赖审计仍有 14 项关联告警：1 low、6 moderate、6 high、1 critical。
  生产依赖中有 5 项低/中等级告警，涉及 Monaco/DOMPurify、PPTX/ECharts/uuid；
  开发工具链另涉及 Capacitor assets/CLI、sharp、xcode、tar、browserslist、nanoid 和 postcss，
  其中 critical 为 Capacitor assets 间接引入的旧版 tar。关联告警数不等于独立漏洞数。
  这些链条在本批之前已存在；未盲目执行建议降级直接依赖的 audit fix --force，列入 M20。
  审计没有通过，不能把测试通过解释为依赖安全已完成。
- 协议 schema 由 Rust 生成器重新生成，同时补齐基线遗漏的既有事件/插件字段，不增加平行手写协议。

## 复现命令

在项目根目录运行：

```sh
cargo test -p miniq-daemon -p miniq-memory -p miniq-models -p miniq-protocol -p miniq-agent
cargo check --workspace
cargo check --manifest-path apps/desktop/src-tauri/Cargo.toml
cargo fmt --all -- --check
git diff --check
cargo run -p miniq-daemon --example experience_fixture
```

在 apps/desktop 运行：

```sh
npx vitest run
npm run build
npm run dev -- --host 127.0.0.1 --port 1459
```

隔离 daemon 会打印随机端口。把它提供的查询参数附在前端 URL；
预览组件测试页为 /experience-preview.html，仅开发模式可用，不进入正式应用入口。
没有启用调度器、远程控制、生产 Key 或真实模型。
