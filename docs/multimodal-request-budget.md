# 多模态请求大小保护

适用位置：miniq-models 的统一请求编码入口，覆盖 Responses、Chat Completions 和 Anthropic Messages。

## 行为

- 单图继续沿用已有的 7 MiB 安全压缩策略。
- 图片 base64 数据及预估包装开销总预算为 16 MiB。
- 最终 ModelFirstRequest JSON 的实际 UTF-8 字节上限为 24 MiB。文字、工具定义、工具输出和 provider context 也计入。
- 图片按原文件字节 SHA-256 去重。不同路径、相同文件内容只发送一份；不是感知去重，不合并内容相似或格式不同的图片。
- 优先保留最近一批用户图片，然后保留最新图片引用。
- 超出图片预算时，从最早的历史图片开始移除发送副本，保护最近用户附件和最新完整工具图片批次。不会为了通过预算而悄悄丢弃当前比较图。
- 请求中加入 request_image_budget 提示。工具视觉元数据对应项改为 included=false。保留路径、toolCallId 和原本的 image_history 引用，模型可以按小批次重新读取。
- 原始 CompletionRequest、持久会话、档案和源文件均不修改。工具调用 ID、调用配对及签名上下文保留。图片被去掉后，空的 image-only 消息需要协议占位文本；这是发送副本的适配，不改原记录。
- 当前图片批次单独超过预算，或保留必要内容后仍超过完整请求上限时，发送前返回 RequestTooLarge，不访问模型服务。
- 网关实际返回 HTTP 413 或流式 request_too_large 时，也归类为 RequestTooLarge。提示减少图片/附件，或先提取字幕/文本。该错误不原样重试，不展示可能回显私密内容的网关正文。

## 限制与范围

16/24 MiB 是本地安全预算，不代表所有服务商统一限制。服务商仍可能设置更低限制，因此保留明确的 413 提示。

不自动 OCR 用户素材，不修改 view_image 的原图语义，也不把最新比较批次缩减为少数图片。该改动解决历史累计和重复传输问题。需要大量字幕帧时，Agent 应分批读取，或在适合任务且已核对视觉证据的情况下先提取字幕文本。

图片大小在构建 JSON 前逐张编码测量，大小结果在该步骤缓存，避免预检阶段的反复解码。保留图片仍会由适配器编码；没有引入跨请求图片缓存，也没有缓存敏感音频或密钥。

## 验证

新增回归先复现旧实现：不同路径相同内容被发两份；20 张历史图片构成约 28 MB wire payload；25 MiB 文字请求无拦截。修复后均通过。

覆盖：三种协议图片形状计数、实际 UTF-8 JSON 大小、去重后的当前用户引用、included=false、完整工具批次保护、当前用户超限拒绝、原历史与错误标志不变，以及三协议都在 HTTP 之前拦截超限请求。

Agent 原有文件恢复测试的恢复后夹具改成不同像素，避免把“相同图片必须发两份”当作恢复要求。相同文件去重另有专门测试。

本分支不含语音/伙伴测试版的未提交改动。没有调整版本、合并 main 或发布安装包。
