# miniQ 终端版与桌面 SSH 连接

## 当前版本状态

miniQ 已有真正的终端版本：`miniq` 是命令行客户端，`miniq-daemon` 是共享任务后台。它们与桌面端使用同一套会话、Agent、工具、审批和模型设置，并不是另写的一套简化 Agent。

桌面 SSH 入口和 `miniq bridge` 从 **0.1.41** 开始提供。使用 SSH 功能需要桌面端和远端终端版都升级到兼容版本。旧版 CLI 遇到 `bridge` 会报未知子命令，必须更新；桌面升级不会自动替换本机或远端单独安装的 CLI。

已有 CLI 的安装、交互命令和自动化脚本说明见 [terminal.md](terminal.md)。公开下载入口是 [miniQ Releases](https://github.com/LeadingThink/miniQ-releases/releases)。下载包同时包含 `miniq` 和 `miniq-daemon`，二者需要一起安装；不要仅复制 CLI。

## 和本机 ChatGPT 客户端的关系

桌面 SSH 功能的必要条件是远端存在可以供桌面连接的任务服务。CLI 是便捷的安装、启动与配置入口，并非“有一个终端界面就自动支持桌面 SSH”。miniQ 本次增加的桥接层，连接现有 CLI 与现有后台，让完整桌面任务界面可以操作远端实例。

本机 ChatGPT 26.901.51231（8109，bundle identifier `com.openai.codex`）前端安装包中，以下两个资源包含对应实现：

- `remote-connections-settings-e745983ec0d2.js`：SSH 与远程设备分类、发现主机、连接状态、启用/停用、详情、重连、远端安装/认证/重启操作，以及远端项目的绝对路径校验。
- `remote-connection-editor-draft-70caf00ab3e8.js`：SSH 别名与直接主机名两种入口、可选端口和密钥路径、编辑校验。

这些是已安装前端代码中的可观察逻辑；本次没有直接操作其原生界面，也不据此声称已验证每一种后端操作。官方远程连接文档：<https://developers.openai.com/codex/remote-connections>。

| 能力 | ChatGPT/Codex 对照 | miniQ 本次实现 |
| --- | --- | --- |
| 远端运行时 | 通过 SSH 启动远端 CLI 的 app-server | 通过 SSH 启动 `miniq bridge`，连接远端 daemon |
| 主机入口 | SSH 别名、手动主机、发现列表 | 读取本机 SSH 配置的具体别名，也可手动添加 `user@host` |
| 认证 | 使用 SSH 与远端模型账号配置 | 使用 OpenSSH 密钥/ssh-agent；远端单独配置 OneAPI Key |
| 项目和会话 | 项目关联远端 host | 切换执行主机后加载该主机项目和会话；远端使用绝对路径 |
| 会话隔离 | 以 host 标识关联远端数据 | 切换主机重新挂载任务界面，草稿按主机隔离 |
| 断线处理 | 重连/状态/诊断入口 | 连接恢复后同步状态，不重放可能已经执行的操作 |
| 文件和产物 | 通过远端服务访问 | 通过远端 RPC 按需预览、分批读取，避免访问本机同名路径 |
| 安装与升级 | 安装包前端包含远端安装操作 | 本轮要求先安装兼容 CLI；未实现一键远端安装/升级 |
| 复杂 SSH 配置 | 可在界面填写端口/身份文件 | 使用既有 `~/.ssh/config` 管理端口、IdentityFile、ProxyJump |
| 交互式终端 | 独立集成终端能力 | 远端 Agent 可执行命令；本轮不是新增完整交互式终端面板 |

## 首次连接

### 1. 在本机准备 SSH

本机需要可用的 OpenSSH 客户端。先在本机终端完成一次登录，核对目标主机指纹：

```sh
ssh my-server
```

如果需要自定义端口、用户、私钥或跳板机，可由你自己的 SSH 配置统一管理，例如：

```sshconfig
Host my-server
  HostName server.example.com
  User developer
  Port 22
  IdentityFile ~/.ssh/id_ed25519
```

`server.example.com`、用户和密钥文件都是示例，需要替换为你自己的配置。miniQ 的发现列表读取具体的 Host 别名与 Include 文件，不把 `Host *` 当成一台主机，也不为了列出主机执行 `Match exec`。

miniQ 连接使用非交互认证。加密私钥需要先通过系统密钥管理或 `ssh-add` 解锁；只支持每次输入密码登录的服务器暂时不能直接从此入口连接。miniQ 不记录 SSH 密码，也不转发 ssh-agent 到远端。

### 2. 在远端准备 miniQ

当前桌面 SSH 启动方式支持 **Linux/macOS 远端的 POSIX shell**。本机可使用系统 OpenSSH；远端 Windows shell 的启动方式不在本轮支持范围内。

在远端安装 **0.1.41 或更新版本**的同批终端构建，将 `miniq` 和 `miniq-daemon` 放到同一 PATH 目录。开发验证也可以在远端从源码执行 `sh scripts/install-cli.sh`，具体系统依赖见 [terminal.md](terminal.md)。

远端终端中执行：

```sh
miniq --version
miniq configure --base-url https://oneapi.zaiwenai.com/v1 --model MODEL_ID
miniq doctor
miniq bridge --help
```

将 `MODEL_ID` 替换为账号可用的文本模型名称。`configure` 会隐藏输入 API Key；不要把 Key 写进命令参数或 SSH 配置。连接后也可在 miniQ 的服务设置里管理所选主机自己的模型配置。本机 API Key 不会自动复制到远端。

### 3. 在 miniQ 桌面中连接

1. 打开“设置 → 服务与远程”，展开“SSH 连接 · 远程开发”。API Key 设置仍保留在前面。
2. 在发现列表点击主机的“连接”；未列出时，输入具体别名、主机名或 `user@hostname` 后点击“添加并连接”。
3. 连接成功后，状态栏显示 `SSH · 主机名`，左侧加载该主机的项目和会话。
4. 打开已有远端项目，或添加远端绝对目录，如 `/home/developer/projects/demo`。不能用本机文件选择器给远端指定目录。
5. 像本机任务一样发送要求、查看执行过程、处理审批并预览远端产物。

添加入口只保存主机名称。连接失败时保留原来的执行主机及草稿，显示具体原因；不会悄悄切回本机执行。切换成功时清理前一个主机的界面状态，避免项目、错误和待审批事项串到另一台电脑。

“返回此电脑”恢复本机项目。移除主机入口不会删除远端文件、会话或账号配置。正在使用的主机必须先切回本机后才能移除。

## 运行与网络行为

数据路径为：

```text
miniQ 桌面界面
  → 本机仅监听 loopback、带临时认证 token 的连接
  → 系统 OpenSSH 加密通道
  → 远端 miniq bridge
  → 远端用户的 miniq-daemon
```

无需 miniQ relay，也不把远端 daemon 端口公开到网络。不复制本机模型 Key；文件、工具、模型请求与任务状态属于所选远端实例。远端使用其自己的模型设置和网络环境。

断开 SSH、退出桌面或切换电脑只关闭观察连接，不自动取消 daemon 里的任务。重新连上后先查看已保存的执行状态；对于断线时结果不明确的动作，系统不自动重放，以免重复提交、重复写入或重复发送。

已有远端进程可能仍是旧版。替换磁盘上的二进制不等于已经升级正在运行的 daemon；应在远端任务空闲后按正常更新流程重启，不能对运行中的任务强行替换或重复启动。

## 能力边界与排错

| 现象 | 处理方式 |
| --- | --- |
| 找不到 SSH 客户端 | 在本机安装或启用 OpenSSH，确认终端可以运行 `ssh` |
| 主机密钥未信任/发生变化 | 在终端核实主机身份后处理；miniQ 不自动忽略密钥校验 |
| 身份验证失败 | 检查 `ssh my-server` 与密钥、ssh-agent；输入密码登录不等于应用可免密登录 |
| 找不到 miniQ CLI | 在远端把两个 miniQ 可执行文件放入 PATH；使用非交互登录环境再次检查 |
| `bridge` 为未知子命令 | 远端仍是旧 CLI，需要安装本次兼容构建 |
| SSH 已连通但无法发起模型任务 | 配置远端实例自己的 API Key、服务地址与可用模型 |
| 远端电脑控制无法使用 | 需要远端图形会话和对应系统权限；无桌面服务器不会因为 SSH 自动获得图形桌面 |
| 网页记录可看但无法直接操控右侧实时网页 | 本轮 SSH 使用远端网页观察/截图与任务指令，不将本机 WebView 当成远端浏览器 |
| 在本机打开远端网页链接后未登录或打不开 | 本机浏览器不共享远端登录状态；远端 localhost/内网地址也不会自动通过 SSH 转发 |
| 连接断开时任务似乎消失 | 检查状态栏执行主机，重新连接同一主机查看；不要立即重复发送有外部副作用的任务 |

本轮不包含远端浏览器端口转发、完整图形桌面串流、Windows 远端 shell、一键远端安装和完整终端模拟器。已支持的远端任务能力沿用真实 daemon；不以本机代执行来掩盖不支持的功能。

## 本轮验证

- 前端 23 个相关测试文件、186 项测试通过，覆盖 SSH RPC、主机切换隔离、设置、附件/文件路径、远程项目、浏览器隔离、桌面更新以及现有会话行为。
- CLI 19 项测试通过，Clippy 严格检查通过；原生 SSH 15 项测试通过，Tauri 编译检查通过。
- TypeScript 与前端生产构建通过；相关格式与差异检查通过。现有大型预览模块仍有分块体积提示，本轮未改变这些渲染器的体积。
- 在临时密钥、临时配置和仅 loopback 的独立 sshd 上，实际运行 OpenSSH → miniq bridge → daemon 链路，任务中断开后重连，确认任务仍运行、最终回复可恢复、模型请求仅一次。模型接口为本机测试服务，没有调用付费模型。
- 同一隔离环境验证了桌面原生 WebSocket 代理的真实 SSH 健康与项目 RPC；测试后清理全部临时进程、密钥和数据。
- 原生测试覆盖主机切换竞争、失败时保留原主机、同 ID 的旧连接迟到回复不能串入新连接、认证、协议不匹配、分帧中断和退出清理。
- 使用生产 SSH 设置组件在浏览器检查明暗主题、连接成功/失败、当前主机提示和使用说明。演示地址为 `http://127.0.0.1:1424/ssh-preview.html`，全部为合成主机；它本身不建立真实 SSH。

Windows 本机、Linux 本机及另一台物理主机的端到端验收不能由上述 macOS 回环测试替代。具体发布及服务器验收结果以对应版本的发布记录为准。
