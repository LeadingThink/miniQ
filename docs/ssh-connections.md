# miniQ 终端版与统一 SSH 工作区

## 终端版与连接机制

miniQ 有真正的终端版本：`miniq` 是命令行客户端，`miniq-daemon` 是共享任务后台。终端与桌面使用同一套会话、Agent、工具、审批和模型设置。终端安装及使用说明见 [terminal.md](terminal.md)，公开安装包见 [miniQ Releases](https://github.com/LeadingThink/miniQ-releases/releases)。两个可执行文件需要一起安装。

`miniq bridge` 从 0.1.41 开始提供。远端需要包含该命令的兼容终端版；统一主机侧栏和手机访问还要求桌面安装包含本轮改动的版本。旧 CLI 不会因为桌面更新而自动更新。

SSH 连接由本机 daemon 统一维护，每台主机都有自己的连接、状态和请求队列。桌面与手机查看同一份主机目录。本机项目和已连接 SSH 主机的项目同时出现在侧栏；打开另一个主机上的会话只改变正在查看的会话，不替换整个应用或断开其他主机。

对应本机 ChatGPT/Codex 的源码证据、差异及验收边界见 [unified-ssh-workspaces.md](unified-ssh-workspaces.md)。

## 首次连接

### 1. 在桌面电脑上准备 SSH

在运行 miniQ 桌面的电脑上，用终端完成一次登录并核对服务器指纹：

```sh
ssh my-server
```

端口、用户、私钥和跳板机仍由系统 SSH 配置管理，例如：

```sshconfig
Host my-server
  HostName server.example.com
  User developer
  Port 22
  IdentityFile ~/.ssh/id_ed25519
```

以上主机名、用户和密钥路径都是示例。发现列表读取具体 Host 别名和 Include 文件，不把通配符当成具体主机，也不为了发现主机执行 `Match exec`。

连接使用 OpenSSH 非交互认证。加密私钥应先通过系统密钥管理或 `ssh-add` 解锁。miniQ 不保存 SSH 密码，也不把私钥或 ssh-agent 转交手机；只支持每次输入密码的服务器不能直接使用这一连接入口。主机密钥校验仍然有效。

### 2. 在远端准备 miniQ

当前支持 Linux/macOS 远端及其 POSIX shell；远端 Windows shell 不在本轮支持范围内。将同一兼容版本的 `miniq` 和 `miniq-daemon` 放入远端 PATH。开发环境也可按 [terminal.md](terminal.md) 从源码安装。

在远端执行：

```sh
miniq --version
miniq configure --base-url https://oneapi.zaiwenai.com/v1 --model MODEL_ID
miniq doctor
miniq bridge --help
```

将 `MODEL_ID` 替换为账号可用的文本模型。`configure` 隐藏输入 API Key，不要把 Key 放到命令参数或 SSH 配置中。每台远端使用自己的模型设置；本机 API Key 不会自动复制到远端。

### 3. 在桌面保存并连接主机

1. 打开“设置 → 服务与远程”的 SSH 连接区域。
2. 选择发现的主机，或添加具体 SSH 别名、主机名、`user@hostname`。
3. 保存的主机进入本机 daemon 的主机目录。连接后，其项目和会话加入现有侧栏，本机项目继续保留。
4. 打开远端项目，或在该主机下添加远端绝对目录，例如 `/home/developer/projects/demo`。本机文件选择器中的路径不能代替远端目录。
5. 在所选会话继续任务、处理审批和查看产物。任务执行位置由该会话所属主机决定。

已有桌面版本保存在 `miniq.ssh.saved-hosts` localStorage 中的主机，升级后迁入本机 daemon。迁移成功后使用 daemon 的持久化目录；不能把浏览器本地存储当成手机与桌面的共享主机列表。

## 手机访问

先在桌面设置中开启“移动端与远程桌面”，再在手机网页或 App 连接这台桌面。手机沿用原来的加密 relay 连接，即可选择桌面已经保存的 SSH 主机并查看其项目、历史、运行进度和文件。

手机不能通过任意主机名直接创建新的 SSH 连接。可访问范围由桌面保存的主机目录限定，SSH 凭据和系统 SSH 配置始终留在桌面电脑上。手机的远程权限限制同样适用于转发给 SSH 主机的内部方法；`host.call` 不是绕过设置、主机管理或 daemon 关闭限制的通道。

手机需要桌面 daemon 在线且能够连接目标 SSH 主机。远端任务保存在远端 daemon，不需要手机持续在线。手机的“移动问答”仍是独立的直接模型问答模式，不等同于此处的远程工作区。

## 数据路径与隔离

```text
桌面界面 ── 本机连接 ──────────┐
                              │
手机 ── 现有加密 relay ────────┤
                              ▼
                       本机 miniq-daemon
                         ├─ 本机项目与任务
                         ├─ SSH 主机 A → miniq bridge → A 的 daemon
                         └─ SSH 主机 B → miniq bridge → B 的 daemon
```

本机功能和桌面直接使用 SSH 不依赖 relay。只有手机连接桌面时经过 relay；远端 daemon 端口无需公开到网络。

桌面与手机始终保留同一个根连接。访问 SSH 工作区时，通过 `host.call` 携带 `hostId`、内部方法及参数；远端事件通过带 `hostId` 的 `host_event` 分发。界面按主机识别项目、会话、草稿、缓存、产物和待审批事项，避免不同机器上的同名路径或相同记录 ID 串用。

主机发现、保存、移除与连接管理属于本机 daemon。界面不再依赖仅 Tauri 可用的原生 SSH 代理，因此网页与 App 能复用同一套任务和文件访问流程。

## 断线、重连与升级

断开某台主机只关闭该主机的观察连接，不取消它的远端任务，也不影响本机或其他已连接主机。重新连接后读取已保存的任务状态和历史。对于断线时结果不明确的操作，不自动重放请求，以免重复提交、重复写入或重复发送。

移除主机入口不会删除远端文件、会话或模型配置。断开连接和取消任务是两个不同操作；如果确实要停止任务，应在任务界面明确取消。

替换远端磁盘上的二进制，不等于已经升级正在运行的 daemon。应先确认远端任务空闲，再按正常更新流程重启。桌面更新不能强制终止远端任务。

## 排错和能力边界

| 现象 | 检查方式 |
| --- | --- |
| 未找到 SSH 客户端 | 在桌面电脑安装或启用 OpenSSH，确认终端可以运行 `ssh` |
| 主机密钥不可信或变化 | 在终端核实主机身份；不关闭主机密钥校验来绕过问题 |
| 身份验证失败 | 检查密钥、ssh-agent 和非交互登录；终端输入密码成功不等于应用可免密登录 |
| 找不到 `miniq` 或 `bridge` | 检查远端非交互 PATH，并更新 CLI 与 daemon |
| 连接正常但模型任务失败 | 检查远端自己的 API Key、模型、协议和网络 |
| 手机看不到某个 SSH 主机 | 确认主机已在这台桌面保存，且桌面使用包含统一工作区的构建 |
| 一个主机断开 | 在该主机分组查看错误并重连；其他主机与本机仍可使用 |
| 远端文件预览失败 | 确认文件存在于会话所属主机，并有相应工作区读取权限 |
| 无图形界面的服务器无法电脑控制 | 需要远端图形会话及系统权限；SSH 本身不会创建图形桌面 |
| 远端网页在本机浏览器无法登录 | 本机浏览器不共享远端登录状态，远端 localhost 也不自动映射到本机 |

本轮不包含一键远端安装升级、远端 Windows shell、完整图形桌面串流、通用浏览器端口转发或完整交互式终端模拟器。Agent 仍可在远端执行已有命令工具。

## 验收

自动检查覆盖主机路由、连接隔离、移动远程权限和事件分发。真实隔离 SSH 检查使用临时密钥、临时数据目录和仅监听 loopback 的 sshd；执行入口为：

```sh
node scripts/test-ssh-smoke.mjs
```

该脚本不连接生产主机或真实模型，也不使用真实用户的 SSH 配置、任务或模型凭据。本轮已通过组合烟测：加密移动 relay → 本机 daemon → SSH bridge → 远端 daemon，可读取运行中会话、文件和带主机标识的事件；独立断开、重连后原任务完成，模型调用恰好一次。此前授权的真实 Linux SSH 服务器也通过连接、健康状态及空目录读取检查。

详细结果与限制见 [unified-ssh-workspaces.md](unified-ssh-workspaces.md)。Windows/Linux 本机与手机真机界面验收不能由 macOS 回环测试替代；真实服务器的空目录检查也不代表已测试真实远端任务。
