# miniQ 产品报告

## 一句话定位

miniQ 是一个运行在桌面工作区里的 AI Coworker：用户只描述目标，Agent 负责规划、读取本地资料、调用工具、执行任务并交付可直接使用的文件；涉及风险的动作在执行前询问用户。

## 产品能力

- **目标驱动执行**：从自然语言目标开始，自动拆解计划并在时间线中展示执行步骤。
- **工作区原生**：文件读取、搜索、编辑、补丁、Git、Shell、文档读写都围绕当前 workspace 工作，路径受 sandbox 约束。
- **多格式产物**：可读取 PDF、DOCX、XLSX、PPTX、CSV，并生成 DOCX、XLSX、Markdown、CSV。
- **浏览器与外部工具**：支持网页搜索、网页读取、HTTP、浏览器自动化和 MCP server，统一进入审批与审计链。
- **可控自治**：风险等级与审批模式共同决定是否需要确认；blocked 动作拦截。支持允许一次、本会话允许，工具写入 checkpoint 和回滚。本次实录使用 alwaysAsk。
- **技能系统**：技能按项目、用户、内置三级发现；任务完成后可将 transcript 蒸馏为 SKILL.md，并支持后续演进。
- **持续任务**：已安排任务可用于每日简报、周报和项目巡检等重复工作。
- **会话连续性**：可发现并导入本机 Codex、Claude Code、OpenCode 历史会话，在 miniQ 中继续工作。

## 核心特色

1. **从聊天到交付闭环**：不止回答问题，而是把结果落到工作区，形成报告、表格和代码改动。
2. **可见且可干预的执行**：计划、工具调用、审批、产物和审计记录都可见，用户始终知道 Agent 在做什么。
3. **安全粒度细**：风险按工具、程序、域名、MCP server 分层控制，兼顾效率与边界。
4. **越用越贴合团队**：一次任务可以沉淀为技能，重复任务不必从零描述。
5. **开放而非封闭**：OpenAI-compatible provider、MCP、WASM/Node 插件和外部会话导入提供扩展空间。

## 与市场产品对比

| 维度 | miniQ | ChatGPT / Claude 网页端 | Cursor / IDE Agent | Zapier / 通用自动化 |
|---|---|---|---|---|
| 工作入口 | 桌面工作区 | 对话网页 | 代码编辑器 | 预设流程画布 |
| 本地文件与代码 | 原生 workspace + 工具链 | 通常需上传或连接器 | 强，聚焦代码 | 依赖连接器 |
| 任务执行 | 多步 Agent 自主执行 | 以回答和有限动作调用为主 | 代码任务强 | 固定触发器/动作 |
| 风险控制 | 分级审批、checkpoint、审计 | 依产品和连接器而定 | 以代码变更审阅为主 | 权限配置为主 |
| 结果交付 | docx/xlsx/md/csv 与代码改动直接落盘 | 文本或下载 | 代码改动 | 外部应用记录 |
| 技能沉淀 | transcript 蒸馏为可复用技能 | 自定义指令/项目知识 | Rules / instructions | 模板化流程 |
| 开放性 | MCP、插件、兼容模型、会话导入 | 生态强但边界由平台决定 | IDE 生态强 | SaaS 连接器生态强 |

## 目标用户与典型场景

- 独立开发者：理解仓库、修复问题、生成变更说明和发布材料。
- 产品与运营：从资料整理产品报告、周报、竞品调研和项目巡检。
- 小团队：把重复的简报、审查、汇总流程沉淀成技能和定时任务。
- 对安全敏感的团队：需要人工审批、可回滚和完整审计的 Agent 工作流。

## 视频传播建议

宣传片应把差异集中在一条主线：**“你说目标，它来执行；关键一步，先问你；做完一次，下次更快。”**

最终宣传片为 78 秒，1920×1080，30 fps，H.264/AAC，无旁白，120 BPM 合成电子音乐与操作音效。0–38 秒为明确标注的功能动效；38–58 秒为真实桌面及移动浏览器同一会话的远程审批、续接及完成画面；58–72 秒说明模型协议并展示真实设置；72–78 秒品牌收尾。

## 移动远程工作流

桌面与移动端使用同一个 API Key 派生远程身份，通过 relay 连接；消息使用 AES-256-GCM 加密。远程同步的是项目、会话、任务和审批，不是屏幕镜像或通用远程桌面。可查看任务、批准操作、发送续接消息及取消任务；本次没有验证暂停功能。

本次在本机隔离 daemon 与 relay 上运行真实产品，Chrome 移动视口模拟手机浏览器，不是实体手机或公网部署验证。手机批准 file_write 后，桌面实际创建了发布摘要；手机继续要求读取文件，桌面调用 file_read 并给出提醒。远程设置修改、daemon 关闭等敏感操作有限制；视频中的模型设置来自本地桌面。

## 模型与 API 协议

| 协议选项 | 对应接入场景 | 边界 |
|---|---|---|
| OpenAI Responses | GPT、o、Codex 系列及兼容网关 | 服务商必须接受该协议和工具格式 |
| Anthropic Messages | Claude 原生消息、流式与工具调用 | 原生适配不等于任意代理地址均可用 |
| OpenAI Chat Completions | OpenAI 兼容接口；国内外网关中的 DeepSeek、GLM、Kimi、Gemini、Grok 等 | 模型名称与文本、工具、流式支持依网关而异 |
| Auto | 自动选择适配协议 | 遇到非标准网关时可显式选择协议 |

历史网关兼容性测试见同目录 oneapi-model-compatibility-20260903.md。该测试包含文本和工具调用，不是模型质量排名，也不保证其他渠道、当前版本或所有型号可用。本次视频实际模型 ID 为 gpt-6-astra，使用 Chat Completions；最初 Responses 请求被该网关以 Unsupported tool type: apply_patch 拒绝，切换协议后完成文件写入及读取。不能据此宣称该网关的 Responses 全面兼容。

## 当前边界

miniQ 的优势是开放、可控、工作区原生和可扩展；相比成熟 SaaS，连接器数量、跨平台分发和非技术用户的开箱体验仍是需要持续建设的方向。视频中应突出已实现的工作区 Agent、审批、产物、技能和定时任务，不夸大为“完全自动化”。
