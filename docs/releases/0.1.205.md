# miniQ 0.1.205 / Android 0.1.112

## Claude 图片下载超时

使用 Anthropic Messages 协议时，图片会被替换成七牛云的短期签名链接，网关收到请求后自己去拉取该地址。跨境访问超过网关时限时，整条请求失败并返回：

```
provider returned 400: {"error":{"type":"<nil>","message":"The request timed out while trying to download the file. Please try again later."},"type":"error"}
```

此时模型没有收到任何内容，重试会复用同一批链接，所以十次重试基本都失败。

本版改动：

- Anthropic Messages 协议不再使用上传通道，始终发送内联 Base64 图片块（`source.type: base64`）。请求自包含，绕开网关下载步骤。Chat Completions 和 Responses 仍使用链接，行为不变。
- 图片链接的内存缓存刷新余量从 60 秒提高到 300 秒。此前剩余寿命不足 60 秒才重传，一个仍"有效"但只剩几秒的链接会被复用，网关可能在下载途中遇到过期。签名链接有效期本身保持 15 分钟，会话历史仍不保存任何链接。

小图（几十 KB 的截图）此前也可能成功，因为网关下载在时限内完成；失败与体积和当时链路速度相关，不是域名不可达。

## 其他一并发布的改动

- 技能提示改为按当前请求排序的短名单，并注明匹配数与启用总数，不再每轮附带完整目录。
- 文件搜索改为并行遍历，结果按路径和行号排序以保持分页稳定；新增单次收集上限，超出时 `total` 仍精确并提示收窄搜索范围。
- 命令未找到的识别不再依赖 PowerShell 界面语言，覆盖中文 Windows 的本地化报错文本。
- 系统提示补充两点：可直接回答的问题不建计划不调工具；首次工具批次前用一句话说明要检查什么。

## 验证范围

本版未在本地编译。发布由 `Release Desktop Update` 工作流在 Windows x64、macOS Apple Silicon、macOS Intel 和 Linux x64 上构建并验证，Android 由同一工作流独立构建并校验签名、versionCode 与 APK 哈希。真实 Windows、macOS、Linux 安装和 Android 真机升级不在本次执行范围内。
