# miniQ 0.1.163 / Android 0.1.82

本次桌面更新包含 [原有未提交功能清单与 FD 修复证据](0.1.161.md)，以及 [Windows 附件测试路径修正](0.1.162.md)：完成命令后回收输出文件、stdin 和 PTY，保留完整历史回放；取消模型 SSE 时释放上游；完善原件上传、文件票据、预览和单文件授权。

## Windows 原生验证发现的问题

0.1.162 发布校验发现 ConPTY 任务无法自行完成。独立 Windows 诊断中，普通管道任务正常完成，而 PTY 任务持续停留在 `exit=None`，输出只有 4 字节的启动光标查询 `ESC[6n`。`portable-pty 0.9` 固定启用 `INHERIT_CURSOR`，要求宿主读取查询并写回光标位置；此前读取器仅归档输出，没有应答。

微软文档明确要求后台处理该握手，否则初始化或 `ClosePseudoConsole` 可能阻塞：

- [CreatePseudoConsole 的 INHERIT_CURSOR 要求](https://learn.microsoft.com/en-us/windows/console/createpseudoconsole)
- [关闭伪终端时的死锁说明](https://learn.microsoft.com/en-us/windows/console/creating-a-pseudoconsole-session)

读取器现自动消费并回答第一次启动查询，随后应用查询继续透传给终端界面，避免重复应答进入子进程 stdin。解析支持任意读取边界，并完整保留其余字节及 EOF 时不完整的前缀。应答先于输出写盘，避免磁盘错误跳过握手；读取器仅临时升级输入句柄的弱引用，不延长任务输入资源的生命周期。

macOS Intel 发布构建另触发 Vite 默认约 2 GiB 的 Node 堆上限。正式构建与普通构建工作流统一为打包步骤设置 4 GiB Node 堆。
