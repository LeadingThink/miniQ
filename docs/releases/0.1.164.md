# miniQ 0.1.164 / Android 0.1.82

本次更新包含 [未提交功能清单与 FD 修复证据](0.1.161.md)、[Windows 路径测试修正](0.1.162.md) 和 [ConPTY 启动握手修复](0.1.163.md)。完成命令后回收输出文件、stdin 和 PTY，保留完整分页回放；取消模型流时释放上游，完善手机原件上传、文件票据、预览与单文件授权。

## 大文件发布修复

0.1.163 的各平台构建、原生回归与 macOS 签名公证均通过，但七牛上传的默认 4 MiB 分片在 GitHub Actions 到对象存储的链路上发生 socket 超时。仅改为 HTTPS 或将超时延长到 120 秒仍出现 504 与读取超时。

独立临时对象诊断验证了官方 SDK 的 HTTPS、1 MiB 分片、120 秒连接及读写超时配置：所有分片与合并请求成功，远端文件大小正确，实际下载后的 SHA-256 与源文件一致，诊断对象已删除。表单上传对照未通过，不作为回退路径。发布器继续使用官方 V2 分片上传，按 bucket 查询完整区域列表，保留安装包先于稳定清单发布的顺序。

诊断工作流：[39395543086 的 multipart-v2 job](https://github.com/LeadingThink/miniQ/actions/runs/39395543086/job/118537270053)。整个对照工作流因表单上传失败而显示失败，不能将其视为正式发布成功。

## 本地发布检查

- 前端 344 个测试文件、2,630 项 Vitest 测试及附加脚本检查通过，TypeScript / Vite 构建通过。
- daemon 447 项通过、1 项忽略；Rust 格式、workspace 与 Tauri 检查、版本一致性及 diff 检查通过。
- 发布脚本 49 项 unittest、Ruff 检查及上传器 mypy 检查通过；覆盖区域隔离、超时、异常脱敏、远端大小与哈希不符、分批进度输出。
- FD 回归沿用已通过的 64 FD 上限测试：保留 192 个任务、384 次完整回放，任务完成后的 FD 基线、峰值和最终值均为 9。

## 发布范围

桌面使用新的 `v0.1.164` 标签，不移动既有标签。Android 保持已发布的 0.1.82，Relay 与手机网页已部署对应功能。

本机仍在运行的 0.1.160 daemon 不会因源码更新自动获得修复。安装桌面更新并在会话空闲时重启后，修复才会生效。
