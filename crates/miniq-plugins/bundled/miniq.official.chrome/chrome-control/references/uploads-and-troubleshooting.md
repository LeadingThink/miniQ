# 文件上传与常见故障排查

## 文件上传

### 用户的 Chrome（app_automation）
1. **确认**要上传的文件路径和目标站点。上传属于“可预先授权”一类，见 safety-confirmations.md。
2. 对“选择文件”或“上传”按钮执行 `invoke AXPress`，系统会弹出文件选择面板。
3. **文件面板是异步加载的**：
   - 面板刚出现时，文件列可能还是空的。
   - 这时重新执行 `inspect`，等它就绪。
   - 不要重开面板，也不要猜测控件。
4. 最稳的方式是按 `key "g"` 加 `modifiers:["meta","shift"]` 打开「前往文件夹」：
   1. `type` 输入完整路径。
   2. `key Enter`。
   3. 重新 inspect，确认目标文件已被选中。
   4. 对「打开」或「上传」按钮执行 `invoke AXPress`。
5. 在网页里验证：文件名出现在表单中，或出现上传进度或缩略图。
6. **拖拽上传区**（没有按钮、只能拖入）：
   - 这需要 computer_use 从访达拖拽过去，事先要告知用户。
   - 很多站点的拖拽区其实也可以点击，先试点击。

### 内置浏览器（browser_automation）
- 内置浏览器会弹出系统文件面板，处理方式同上：面板属于 miniQ 应用，用 app_automation 操作。
- 如果站点有“通过 URL 导入”或 API 上传，优先使用这些方式。

### 上传失败时逐项排查
| 现象 | 可能原因 | 处理 |
|---|---|---|
| 面板里找不到文件 | 路径有误，或文件在 iCloud 中未下载 | 用 `ls -l` 确认文件存在；让 iCloud 文件先下载到本地 |
| 选择后没有反应 | 站点限制文件类型或大小 | 读页面提示和 `accept` 限制，告诉用户需要转换格式或压缩 |
| 进度条卡住 | 网络问题或文件过大 | 等待并观察 1–2 次；仍然卡住就报告，不要反复提交 |
| 上传了错误的文件 | 面板里选错了 | 在最终提交前删除附件并重新选择；如果已提交，告诉用户 |

## 常见故障
| 现象 | 处理 |
|---|---|
| osascript 30 秒无响应 | 系统可能在等「自动化」授权弹窗，或 Chrome 有模态对话框。请用户查看屏幕 |
| 错误 -1743 | 请用户在「系统设置 → 隐私与安全性 → 自动化」中允许 miniQ 控制 Chrome |
| 错误 -600 或“未运行” | Chrome 没有打开；征得同意后执行 `open -a "Google Chrome"` |
| execute javascript 报错 | 用户没有开启“允许 Apple 事件中的 JavaScript”，改用 AX 路线；不要替用户开启 |
| AX 树只有工具栏、没有网页 | 窗口最小化了，或网页仍在加载，稍后重新 inspect；也可以改用截图 |
| 点击后页面没变化 | 元素被遮挡（Cookie 横幅、弹窗）或不可交互：先关掉遮挡，再按键盘 → 坐标点击的顺序升级 |
| 被识别为机器人、弹出验证码、被限流 | 停止并告知用户；不更换身份，不绕过 |
| 页面要求重新登录 | 交给用户登录，完成后继续 |
| 页面内容与预期完全不同 | 可能是钓鱼页或跳转劫持：停止操作，报告网址 |

## 任务中断与恢复
- 用户中途要求暂停时，立即停止输入，并调用 release。
- 恢复时，先用 `chrome_tabs.py list` 和 inspect 重新观察，不要沿用旧的 observationId 或旧截图。
- 长任务每完成一个阶段，就向用户简短汇报一次进度。
