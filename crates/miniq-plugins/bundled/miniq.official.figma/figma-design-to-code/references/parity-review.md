# 还原度评审与写入后自检

适用：①实现完成后的自检（design-to-code 第 7 步）；②用户只要求“评审某页面与 Figma 是否一致”。

## 1. 收集证据（缺什么就明确说缺什么）
| 证据 | 来源 |
|---|---|
| 设计参考截图 | `get_screenshot`（整页 + 各区块），或 `figma-rest-export` 导出 PNG（`--scale 2`） |
| 设计结构与数值 | `get_design_context`、`get_metadata`、`get_variable_defs` |
| 实现代码 | `file_read` 相关组件、样式、令牌文件 |
| 实现截图 | `shell_run` 后台启动开发服务器 → `browser_automation` 打开页面，视口宽度 = 设计画板宽度，截整页与区块 |
| 静态检查结果 | `python3 scripts/parity_check.py --git --tokens <令牌文件>` |
没有实现截图或设计截图时，不要凭想象下结论；向用户索要或说明“未验证”。

## 2. 对比清单（逐区块）
**布局**
- [ ] 区块顺序、层级、对齐方式一致
- [ ] 间距（gap/padding/margin）与设计一致或使用了对应令牌
- [ ] 宽高、最大宽度、圆角一致；在设计宽度下无意外换行
- [ ] 没有残留参考代码的绝对定位导致的错位
**排版**
- [ ] 字体族、字号、字重、行高、字距一致
- [ ] 文案与设计一致（没有残留 “Title”“Lorem ipsum” 等占位文字）
- [ ] 长文本截断/换行行为合理
**颜色与效果**
- [ ] 背景、文字、边框颜色使用令牌且值正确；透明度正确
- [ ] 阴影、模糊、渐变、描边位置正确
- [ ] 暗色模式（若设计有）正确
**资源**
- [ ] 每个图标/图片都存在、来自设计导出，尺寸与裁剪正确
- [ ] 无过期 MCP 资源链接、无占位图、无手绘 SVG
**组件与状态**
- [ ] 复用了项目已有组件；Code Connect 映射的组件被正确使用
- [ ] hover/focus/disabled/loading/空态/错误态已实现（或注明设计未定义）
**响应式与无障碍**
- [ ] 常见断点（如 375 / 768 / 1280 / 设计宽度）无溢出、无横向滚动
- [ ] 语义标签、可访问名称、焦点可见、对比度
**工程**
- [ ] 构建、类型检查、lint、已有测试通过
- [ ] `parity_check.py` 无 error，warn 已处理或有理由

## 3. 视觉对比方法
1. 两张图用相同宽度（设计画板宽）与相同缩放比例截取；设计图若是 2x，实现截图也用 2x（或把设计图缩回 1x）。
2. `view_image` 分别查看；先整体轮廓，再逐区块放大看细节（字重、1px 描边、圆角、图标对齐）。
3. 如需量化，可用 python3 标准库之外的工具前先确认已安装；无依赖时以人工比对为准，并记录观察到的差异坐标/区块。

## 4. 严重程度
- **阻断**：缺失区块/资源、错误组件、布局崩坏、文案错误、无法交互。
- **明显**：颜色/字号/间距与设计差异肉眼可见；缺少设计中定义的状态。
- **细微**：1～2px 偏差、抗锯齿差异、浏览器字体渲染差异。
- **有意偏离**：因无障碍、项目约定或技术限制而偏离，需说明理由。

## 5. 评审输出格式
```
## 还原度评审：<页面/组件名>
证据：设计 <链接/节点>；实现 <文件/URL>；已比对截图：是/否
### 问题（按严重程度）
1. [阻断] <区块> — 设计：… 实现：… 位置：<file:line> 建议：…
2. [明显] …
### 有意偏离
- …
### 未验证项
- …（原因）
### 结论
通过 / 需修复 N 项后复查
```
先列问题，再给总结；不要用“整体不错”掩盖具体差异。
