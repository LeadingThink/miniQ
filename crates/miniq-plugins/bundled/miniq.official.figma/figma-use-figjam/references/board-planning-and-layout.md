# 白板内容规划与布局

## 1. 先规划，再写入

写入之前，先在对话中给出一份结构草案。用户不需要确认也可以直接执行，除非内容归类有歧义。草案格式如下：

```
画板：冲刺 23 回顾（放在现有内容右侧）
分区 A「做得好」绿色：便利贴 ×4
分区 B「待改进」红色：便利贴 ×5
分区 C「行动项」蓝色：表格 3 行（负责人/事项/截止）
连线：B 中的 2 条 → C 对应的行动项
```

规划原则：

- **一条想法写一张便利贴**，每张不超过 60 个字。超过的话，要么拆成多张，要么用宽版便利贴。
- **用分区表达分类，用颜色表达语义，用连线表达因果或流程**。三种方式不要混用来表达同一种信息。
- 整块白板使用 4–5 种颜色。
- 标题使用纯文字，字号 48–64；分区名直接用 Section 的 `name`。

## 2. 常见模板

| 场景 | 结构 |
|---|---|
| 回顾会 | 横向 3 个分区：做得好 / 待改进 / 行动项（行动项用表格或蓝色便利贴） |
| 头脑风暴 / 亲和图 | 左边是未分组的便利贴池，右边是按主题聚类的若干分区，分区名就是主题 |
| 看板 | 横向排列：待办 / 进行中 / 已完成 / 阻塞，每列一个分区，卡片从上往下纵向排列 |
| 用户旅程 | 顶部一行是阶段（ShapeWithText），下方每一行分别是：行为、想法、情绪、痛点、机会（便利贴按列对齐） |
| SWOT | 2×2 的四个分区：优势（绿）/ 劣势（红）/ 机会（蓝）/ 威胁（橙） |
| 会议纪要 | 标题文字、议程表格、决策（绿色便利贴）、待办（蓝色便利贴，附负责人） |
| 简单流程 | 用 ShapeWithText 做节点（开始/结束用 ELLIPSE，判断用 DIAMOND，步骤用 ROUNDED_RECTANGLE），用 ELBOWED 连线连接。复杂的流程图交给 figma-generate-diagram |

## 3. 定位：放在现有内容之外

计算现有内容的包围盒（只读，或者在写入脚本的开头计算）：

```js
let minX = Infinity, minY = Infinity, maxX = -Infinity, maxY = -Infinity
for (const n of figma.currentPage.children) {
  const b = n.absoluteBoundingBox
  if (!b) continue
  minX = Math.min(minX, b.x); minY = Math.min(minY, b.y)
  maxX = Math.max(maxX, b.x + b.width); maxY = Math.max(maxY, b.y + b.height)
}
const empty = minX === Infinity
return { empty, bbox: empty ? null : { minX, minY, maxX, maxY }, origin: empty ? { x: 0, y: 0 } : { x: maxX + 200, y: minY } }
```

- 把 `origin` 作为新内容的左上角。白板很宽时，可以改为放在下方，即 `{ x: minX, y: maxY + 200 }`。
- 用户指定了“放在某个节点旁边”时，以该节点的 `absoluteBoundingBox` 为基准，偏移至少 100。

## 4. 网格排布

| 元素 | 尺寸 | 建议间距 |
|---|---|---|
| 方形便利贴 | 240×240 | 24 |
| 宽版便利贴 | 416×240 | 24 |
| 流程形状 | 约 200×100 | 横向 80、纵向 60（给连线留出空间） |
| 分区内边距 | — | 48，顶部额外留 40 给标题 |
| 分区之间 | — | 120–200 |

列数经验：每个分区内每行放 3–4 张便利贴；看板每列只放 1 张。

计算方法：`x = PAD + col * (w + GAP)`，`y = PAD + 40 + row * (h + GAP)`。各元素宽度不同时，按实际宽度逐个累加，不能用固定步长。

## 5. 分区尺寸与多分区横排

1. 先创建所有分区，并算出每个分区应有的尺寸：
   - 宽 = `PAD*2 + cols*w + (cols-1)*GAP`
   - 高 = `PAD*2 + 40 + rows*h + (rows-1)*GAP`
2. 分区横向排列：下一个分区的 `x` 等于上一个分区的 `x + width + 160`。所有分区对齐到同一个 `y`；如果希望视觉更整齐，可以统一使用最高分区的高度。
3. 放入子节点后，重新计算包围盒并调用 `resize`，防止内容溢出。

## 6. 分批与校验

- 每次调用创建的节点不超过约 40 个。按“分区 + 分区内的内容”为单位拆分调用。连接线放在最后一次调用中统一创建。
- 每次调用都要返回按用途归类的 ID 映射，例如 `{ sections: {A: id}, stickies: {A: [..]} }`，供后续连线和修改使用。
- 校验时：
  1. 用 `get_metadata` 检查分区子节点是否全部落在分区内部；
  2. 用 `get_screenshot` 检查整个分区区域，确认没有重叠、文字没有溢出、颜色语义统一。
- 发现重叠时，只移动本次创建的节点，不要移动用户原有的内容。
