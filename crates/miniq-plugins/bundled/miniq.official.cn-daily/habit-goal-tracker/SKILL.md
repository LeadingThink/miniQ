# 习惯与目标追踪

## 适用场景
- "新建习惯：每天背 20 个单词；每周健身 3 次。"
- "今天冥想和跑步都打卡了。"
- "我英语学习连续多少天了？本月完成率呢？"
- "目标：2026 年底前跑完一次半马，帮我拆里程碑。"
- "画个最近 90 天的打卡热力图。" / "今天周一，做个上周回顾。"

## 前置条件
- 数据文件（首次使用时用 `file_write` 创建，之后用 `file_read` + `file_edit` 增量修改）：
  - `追踪/habits.json`：习惯定义与打卡记录
  - `追踪/goals.md`：目标、里程碑与进度日志
  - `追踪/回顾/<YYYY-Www>.md`：每周回顾
- 日期一律 `YYYY-MM-DD`，"今天"按本地日期；"上周"= 上周一至周日；周编号用 ISO 周（如 `2026-W42`）。
- 可视化前 `skill_read visual-charts` 并遵守 `visual-language-core` 规范。

## 数据格式
`追踪/habits.json`（字段固定，新增字段要向后兼容）：
```json
{
  "version": 1,
  "habits": [
    {
      "id": "meditation",
      "name": "冥想",
      "cadence": {"type": "daily"},
      "created": "2026-10-01",
      "archived": false,
      "allowSkipsPerMonth": 2,
      "logs": ["2026-10-01", "2026-10-02"],
      "skips": []
    },
    {
      "id": "gym",
      "name": "健身",
      "cadence": {"type": "weekly", "target": 3},
      "created": "2026-10-01",
      "archived": false,
      "allowSkipsPerMonth": 0,
      "logs": [],
      "skips": []
    }
  ]
}
```
`追踪/goals.md`：每个目标一个二级标题，含"截止日期、衡量方式、里程碑复选框、进度日志（日期 — 事件）"。

## 步骤
1. **新建习惯/目标**：`ask_user` 补齐名称、频率（每日 / 每周 N 次 / 自定义）、开始日期、是否允许"请假"（skip）；目标还要问截止日期、衡量方式（数值或完成态）与 3–6 个里程碑。写入文件后复述一遍。`id` 用英文或拼音小写连字符，禁止空格。
2. **打卡**：`file_read` 读取 JSON → 把今天（或用户指定日期）追加到对应 `logs`（去重）→ `file_edit` 写回。多个习惯一句话打卡时一次处理完。补昨天的卡要用户明确说"补"。
3. **请假**：用户说"今天 X 请假"→ 写入 `skips`，并检查当月 `skips` 数 ≤ `allowSkipsPerMonth`，超出则提示将中断连续。
4. **统计规则**（每次查询现算，不缓存）：
   - 每日习惯连续天数：从今天往回数，`logs` 或 `skips` 命中则 +1，首个缺失日停止；今天未打卡不算中断，但要提示"今天还没打卡"。
   - 每周习惯：本周 `logs` 数 / `target`；"连续周数"= 连续达标的 ISO 周数。
   - 完成率：周 = 本周应完成次数中已完成占比；月 = 自然月同理；用百分比保留整数。
   - 目标进度：里程碑完成数 / 总数，数值型目标用 当前值 / 目标值。
5. **查询回复**：用表格给"习惯｜今日｜连续｜本周完成率｜本月完成率"；目标用"目标｜截止｜进度条（▓▓▓░░ 60 %）｜下一里程碑"。连续 ≥ 7/30/100 天时顺带一句肯定，不煽情。
6. **可视化**（用户要求或周回顾时）：把 `logs` 整理成 `{date, count}` 数据，`skill_read visual-charts` 后生成单文件 HTML：GitHub 风格热力图（主色 松绿 #2E8B57 五档深浅，周一在上，中文星期与月份标签）、每个目标一条进度条；指定中文字体栈；输出到 `追踪/图表/<YYYY-MM-DD>-热力图.html`，用 `browser_automation` 打开截图并 `view_image` 自检（无方块字、无截断），需要 PNG 时一并保存。
7. **每周回顾**（每周一首次对话或用户要求时主动提议）：`file_write` 到 `追踪/回顾/<YYYY-Www>.md`，模板：
   ```markdown
   # 周回顾 YYYY-Www（MM-DD 至 MM-DD）
   ## 数据
   习惯表（名称｜本周完成｜目标｜连续）｜目标进度变化
   ## 做得好的（1–3 条，引用具体日期）
   ## 没做到的与原因（用户口述，不替用户归因）
   ## 下周调整（只改一件事）
   ## 下周重点目标里程碑
   ```
   "没做到的与原因"和"下周调整"用 `ask_user` 请用户填，不要替用户编。
8. **归档/删除**：归档只把 `archived` 设为 `true` 保留历史；删除整条习惯或目标必须 `ask_user` 确认并说明不可恢复，建议先归档。

## 注意事项 / 安全
- 数据全部在本地工作区，不上传、不写入 `memory_write`（偏好类如"每周一提醒回顾"除外，需用户同意）。
- 修改 JSON 前先 `file_read` 最新内容再 `file_edit`，避免覆盖；写回后 `file_read` 校验是否仍为合法 JSON。
- 不替用户打卡：只有用户明确说完成了才记录；不对未打卡做道德评判，只给数据与一条可执行建议。
- 用户要求同步到 Apple 提醒事项或日历时，交给 `apple-notes-reminders`，本 skill 不直接操作其他应用。
- 文件中若有健康类敏感信息（体重、病情），导出或可视化前提醒用户。

## 如何确认完成
打卡已写入且 JSON 合法；统计数字能由 `logs` 手工复算；热力图截图自检通过且中文正常；周回顾文件已生成，且"原因/调整"两栏由用户填写而非 AI 编造。
