# Dropbox 查找与浏览

## 触发场景
- “找一下去年的合同 PDF”“给我看那张团建照片”“我最近改过哪些文件”“/项目 目录下都有什么”“这个数字出自哪份文档”。

## 前置条件
- 插件启用后会自动接入 MCP 服务器 `dropbox`（`mcp-remote` → `https://mcp.dropbox.com/mcp`）。首次调用时会在浏览器中弹出 Dropbox OAuth 授权，请用户登录并授权后重试。
- 先执行 `mcp_call {server:"dropbox", tool:"tools/list"}` 确认可用工具和参数 schema，工具名以返回结果为准。
- MCP 不可用时，按 `references/mcp-and-rest.md` 的顺序退回：先用本地同步目录（`~/Library/CloudStorage/Dropbox*` 或 `~/Dropbox`），再用 HTTP API（需要用户自行在环境变量中设置 `DROPBOX_ACCESS_TOKEN`，miniQ 不索要、不回显）。

## 分步流程
1. **拆解线索**：关键词（文件名或正文）、类型（pdf/图片/表格）、大致时间、可能的目录、创建人。
2. **搜索**：`mcp_call {server:"dropbox", tool:"search", arguments:{query:"合同 2024", ...}}`（类型或路径过滤参数以 schema 为准）。结果较多时优先按修改时间和路径相关性排序；需要更多结果时按分页参数继续获取。
3. **最近文件**：MCP 没有专门的“最近”工具时，在用户常用目录上用 `list_folder`（可以递归时开启递归，并限制数量），按 `server_modified` 倒序取前 N 个，并注明是在哪些目录范围内得出的。
4. **浏览**：用 `list_folder` 分层展示目录（文件夹在前），每层超过 50 项时按类型汇总。
5. **找出处**：先用 search 按正文关键词检索（支持全文搜索的账户），再对前几个候选调用 `fetch` 读取内容并核对原文，给出匹配片段。
6. **呈现候选**：列出“名称 | 路径 | 类型 | 大小 | 修改时间”。候选不唯一时让用户选择；用户要查看图片或文档时，交给 `dropbox-files` 读取，或用 `dropbox-inspect` 查看详情。
7. **没有结果**：换用同义词、中英文、去掉扩展名，放宽时间范围，再试一次；仍然没有结果时，如实说明已尝试的查询。

## 工具与参数要点
- 搜索词短而准，避免整句；文件名中的日期格式可能多样（2024-06、202406、24年6月）。
- 大目录递归时要设置上限，避免一次拉取数万条；可以先列顶层再逐层下钻。
- 只读操作，不需要确认。

## 质量检查
- 候选列表包含完整路径，用户可以直接定位；“找出处”类结论附带原文片段和文件路径。
- 注明搜索范围和使用的查询词。

## 失败回退
- MCP 不可用：在同步目录中用 `glob`/`grep` 查找；也可以用 HTTP `files/search_v2`（见参考文档）。
- 权限不足：说明是哪个共享文件夹或团队空间无权访问。

## 交付格式
```
查询："合同 2024"（范围：全部，类型：pdf）共 3 个候选
| # | 名称 | 路径 | 大小 | 修改时间 |
请确认要打开哪一个。
```
