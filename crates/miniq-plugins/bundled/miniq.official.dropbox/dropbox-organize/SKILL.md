# Dropbox 文件夹整理

## 触发场景
- “按年份整理 /照片”“把这些报价单移到 /客户/A 公司”“统一重命名成 日期_名称 的格式”“建一个项目目录结构”。
- 需要删除或清理时，请用 `dropbox-cleanup`（本技能从不删除）。

## 前置条件
- 插件启用后会自动接入 MCP 服务器 `dropbox`（`mcp-remote` → `https://mcp.dropbox.com/mcp`）。首次调用时会在浏览器中弹出 Dropbox OAuth 授权，请用户登录并授权后重试。
- 先执行 `mcp_call {server:"dropbox", tool:"tools/list"}` 确认可用工具和参数 schema，工具名以返回结果为准。
- MCP 不可用时，按 `references/mcp-and-rest.md` 的顺序退回：先用本地同步目录（`~/Library/CloudStorage/Dropbox*` 或 `~/Dropbox`），再用 HTTP API（需要用户自行在环境变量中设置 `DROPBOX_ACCESS_TOKEN`，miniQ 不索要、不回显）。

## 分步流程
1. **摸清现状**：用 `list_folder` 列出源目录（必要时递归并设置上限），统计文件数量、类型和时间分布。
2. **定规则**：与用户确认整理规则（按日期、项目、类型）、命名格式，以及目标根目录。规则有歧义时，先举 3 个例子让用户确认。
3. **生成计划**：写出“源路径 → 目标路径 | 操作（新建/复制/移动/重命名）”对照表。可以用 `file_write` 写到 `/tmp/miniq-dropbox/plan.md`；条目很多时先展示统计和前 20 条。
4. **冲突检查**：用 `get_file_metadata`/`list_folder` 检查目标位置是否有同名文件，并标注冲突的处理方式（改名、跳过）。不会覆盖已有文件。
5. **确认**：`ask_user` 展示计划摘要。用户只是说“整理一下”，没有明确要移动时，默认采用**复制**（保留原件），并说明原因。
6. **执行**：先用 `create_folder` 建目录，再逐条执行 `copy`/`move`（重命名就是同一目录下的 move）。返回异步任务 ID 时，用 `check_job_status` 轮询直到完成或失败，轮询间隔逐步加大。
7. **回读验证**：用 `list_folder` 核对目标目录中的数量和名称；有失败项时单独列出原因。
8. **汇报**：给出成功、跳过、失败数量，以及如何撤销（移动的反向操作清单）。

## 工具与参数要点
- 分批执行（例如每批 ≤ 100 条），每批完成后再继续；中途报错时暂停并询问是否继续。
- 移动共享文件夹或移出共享文件夹会改变其他人的访问权限，需要特别提示。
- 不对目标路径做删除操作；需要清理原件时交给 `dropbox-cleanup`。

## 质量检查
- 执行结果与计划逐条一致；没有意外覆盖；文件总数守恒（复制时目标数量等于源数量）。
- 保留撤销清单（`/tmp/miniq-dropbox/undo.md`）。

## 失败回退
- 409 冲突：按确认过的规则改名或跳过。
- 权限不足：跳过该项并报告。
- MCP 不可用：使用 HTTP `files/create_folder_v2`、`copy_v2`、`move_v2` 或批量接口（见参考文档），同样需要确认。

## 交付格式
- 计划表（执行前）→ 结果表（操作 | 源 | 目标 | 状态）→ 统计（成功/跳过/失败）→ 撤销清单路径。
