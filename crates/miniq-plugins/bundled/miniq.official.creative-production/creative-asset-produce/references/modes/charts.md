# 模式：图表美化（charts）

**先加载 `contracts/exact-content.md`。** 图表的数据、标签、顺序、单位、来源一律不变，只改视觉。

## 核心原则
- 生图模型会写错数字。所以：**数字、轴标签、图例、标题、来源注记都不交给 generate_image**。
- 推荐路径：
  1. 从用户数据（CSV / 表格 / 截图）中逐项抄录到 `creative/chart-data.json`，并请用户或自己对照原始数据核对一次。
  2. 视觉方向用 `generate_image` 只生成**无文字的背景 / 装饰 / 质感层**（例如纸张纹理、渐变、插画化边框）。
  3. 图表本身用 HTML/SVG（`creative-layout-deliver/scripts/layout.html` 改造，或手写内联 SVG 由代码按数据绘制）确定性渲染，再用 `render.sh` 出 PNG。
- 若用户只要“风格参考”而不需要精确图表，可以生成示意图，但必须在交付时明确标注“示意，数据不可读”。

## 方向维度（4–5 个）
- 编辑部风：大标题留白、细线、衬线字体。
- 品牌风：品牌色主导、粗条形、圆角。
- 深色仪表盘：暗背景、荧光高亮一个关键数据。
- 信息图插画：数据旁配无字插画元素。
- 极简打印：黑白灰、适合报告与 PDF。

## 必须保持
- 数据点数量、数值、排序、分组、颜色与系列的对应关系。
- 坐标轴起点（不得截断 Y 轴夸大差异，除非原图就是如此并注明）。
- 来源与时间注记原文。

## 质检
- 用 `view_image`（`detail: original`）对照 `chart-data.json` 逐项核对每个数字和标签。
- 颜色对比度足以区分系列；色弱友好（不要只靠红绿区分）。
