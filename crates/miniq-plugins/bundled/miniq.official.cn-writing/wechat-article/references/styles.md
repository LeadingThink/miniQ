# 公众号长文三种常见风格写法要点

在 `wechat-article` 第 2 步按用户选定的风格读取对应小节。三种风格可以混用，但一篇文章只能有一个主导风格。

## 一、商业观察

**代表读者**：创业者、管理者、产品 / 市场从业者。

**结构**：
1. 开篇（200–300 字）：一个具体的商业现象、公司事件或数字反差。例如"某连锁品牌一年关了 300 家店，利润却涨了 40%"。
2. 提出核心判断（1–2 句）：这件事背后真正的变量是什么。
3. 3–4 节论证：每节 = 案例 + 分析 + 一句小结。案例要有名字、时间、数字；分析讲机制而不是形容词。
4. 结尾（200 字内）：核心观点一句话 + 对读者的 1–3 条行动建议。

**语言**：
- 短句、短段，每段只讲一件事。
- 敢下结论，少用"可能 / 或许 / 一定程度上"。
- 数字要有口径与时间："2025 年 Q3 同比增长 18%"，不是"增长很快"。
- 几乎不用 emoji。

**禁忌**：空讲趋势不举例；把"行业报告称"当来源；结尾"让我们拭目以待"。

## 二、技术科普

**代表读者**：有一定技术背景但不是该领域专家的人，或完全的外行。先用 `ask_user` 确认读者层级。

**结构**：
1. 开篇：读者能感知的问题或现象（"为什么你的手机夜里会自己变热"），而不是技术定义。
2. 用一个生活类比建立心智模型，再给出准确术语。
3. 分 3–5 节逐层深入：是什么 → 怎么工作 → 为什么这样设计 → 局限与误区。
4. 结尾：一张"记住这三点"式的小结 + 延伸阅读链接。

**语言**：
- 一个术语第一次出现时用括号给英文原文，之后统一用中文。
- 用图表 / 代码块代替大段文字描述流程；代码块 ≤ 20 行并带注释。
- 类比用一次即可，不要通篇"就像……一样"。
- 承认不确定："这部分实现细节官方没有公开，以下是基于公开论文的推断"。

**禁忌**：堆术语显得专业；把原理简化到错误；忽略版本与时间（技术内容必须标注"截至 YYYY-MM"）。

## 三、个人叙事

**代表读者**：和作者有相似处境的人（同龄、同行、同一人生阶段）。

**结构**：
1. 开篇：一个具体时刻的画面（时间、地点、动作、对话），不是"最近我一直在想"。
2. 事件推进：按时间或按转折点分 3–5 段，每段有一个真实细节。
3. 转折：发生了什么让作者改变了看法。
4. 结尾：收在一个具体画面或一句话上，不要总结人生道理。

**语言**：
- 第一人称，允许口语、短句、停顿。
- 感受要具体："收到那条消息时我正在挤地铁，差点错过换乘"，而不是"我很震惊"。
- 允许保留犹疑与矛盾，不必每件事都有结论。
- 克制形容词，一个段落最多一个比喻。

**禁忌**：每段末尾升华；用排比制造情绪；把自己写成完美的人；写他人隐私未经同意。

## 通用排版规则（三种风格共用）

- 一级标题即文章标题，正文用二级 `##` 小标题，不要三级以下。
- 段落 ≤ 5 行（按手机 375px 宽估算约 100 字）。
- 中西文之间空格；全角标点；省略号用"……"。
- 加粗一篇不超过 8 处，只用于读者必须记住的句子。
- 引用他人观点用 `>` 块引用并注明出处。
- 文末不加话题标签、不加"点赞 / 在看 / 转发"引导（用户明确要求时例外）。
