# 原型构建规范

## 1. 技术路线选择

| 条件 | 路线 | 说明 |
| --- | --- | --- |
| 工作区有前端项目（package.json 含 react/vue/svelte/next 等） | 项目内新增页面 | 先读 `../../product-design-router/references/existing-codebase.md`，复用组件与 token |
| 无项目，1–6 屏，交互简单 | 单文件 HTML | 复制 `../scripts/prototype-template.html` |
| 无项目，屏幕多或状态复杂，或用户指定框架 | Vite + React/Vue | `npm create vite@latest prototype -- --template react-ts`，需要 node ≥ 18 |
| 静态落地页 | 单文件 HTML（去掉手机外框） | 使用模板 `?frame=0` 模式或直接删除 `.device` 外框 |

## 2. 目录约定

```
design/
  prototype/
    index.html        # 或 Vite 项目
    assets/           # 生成图、真实素材
    README.md         # 屏幕与状态清单
  qa/
    reference/        # 参考图（按屏命名）
    screenshots/      # 原型截图（与参考同名）
    design-qa.md
```

## 3. 交互清单（核心路径必须全部可用）

- [ ] 导航：底部 Tab / 侧边栏 / 顶部导航可切换，当前项有高亮（`aria-current`）
- [ ] 返回：子页面都有返回路径
- [ ] Tab / 分段控件：点击与方向键可切换，面板同步
- [ ] 表单：必填校验、错误提示、提交加载态、成功反馈；输入框 focus 样式
- [ ] 列表：加载态（骨架屏）→ 有数据 / 空态
- [ ] 错误态：至少一处网络失败或校验失败的展示
- [ ] 按钮：hover、active、focus-visible、disabled 四态
- [ ] 弹层（如有）：打开、关闭、Esc 关闭、点遮罩关闭
- [ ] 非本次范围的入口：用 Toast 提示“不在本次范围”，不做死链接

不做：真实登录、注册验证码、支付、后端 API、数据库。需要“登录后”状态时直接用模拟用户进入。

## 4. 设计 token

从参考中提取并统一：

| 类别 | 需要的值 |
| --- | --- |
| 颜色 | 背景、表面、正文、次要文字、分割线、主色、主色 hover、危险、成功 |
| 字体 | 字族、正文字号/行高、标题层级（通常 3–4 级） |
| 间距 | 基础单位（4 或 8）与常用倍数 |
| 圆角 | 大/小两级 |
| 阴影 | 卡片、弹层两级 |

## 5. 资产规则

- 槽位清单：位置、显示尺寸、生成尺寸（2 倍）、内容描述、来源。
- 生成时提示词写清主体、构图、风格与配色，并与整体视觉一致；“不要文字”除非图中本就需要文字。
- 图标：优先项目已有图标库；否则使用开源图标库（如 Lucide、Tabler，按许可证使用），不要用 emoji 代替。
- 头像、商品图等可用生成图；不要使用真实人物的肖像或受版权保护的品牌图。

## 6. 模拟数据

- 贴近真实：真实感的人名、金额、日期、状态分布（不全是“测试1、测试2”）。
- 覆盖边界：长标题、0 条、很多条、带特殊字符。

## 7. 自测脚本（browser_automation 步骤）

1. `navigate` 到 `http://127.0.0.1:<端口>/#<首屏>`，`resize` 到目标视口。
2. `screenshot` 首屏 → `view_image`。
3. 按核心路径依次 `click` / `type`，每一步 `snapshot` 确认状态变化，关键状态 `screenshot`。
4. 检查控制台错误（如工具提供）或通过页面行为判断。
5. 截图保存到 `design/qa/screenshots/`，命名与参考图一致。
