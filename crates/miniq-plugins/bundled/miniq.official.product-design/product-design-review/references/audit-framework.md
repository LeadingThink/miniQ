# 设计审计框架

## 1. 六个维度

| 维度 | 看什么 | 典型问题 |
| --- | --- | --- |
| 任务流程 | 核心任务步数、是否有死路、是否可撤销/返回、默认值是否合理 | 注册要 7 步；保存后无法返回列表 |
| 信息层级 | 每屏是否有唯一主要行动；标题/正文/辅助信息层级是否清楚；视线路径 | 三个同等强调的按钮；关键数字埋在正文中 |
| 一致性 | 组件、图标、间距、术语、交互模式是否统一；是否符合平台惯例 | 同一操作在两处叫法不同；两种圆角混用 |
| 反馈与状态 | 加载、空、错误、成功、禁用状态是否齐全且有指引 | 提交后无反馈；空列表只显示空白 |
| 可访问性 | 对比度、触控目标、焦点可见、键盘可达、替代文本、不只靠颜色传达信息 | 浅灰文字 2.8:1；图标按钮无标签 |
| 内容文案 | 清晰、简短、用户语言、按钮是动词、错误信息说明原因与办法 | “操作失败”；按钮写“确定”而不是“保存草稿” |

## 2. 严重度

| 级别 | 定义 | 例子 |
| --- | --- | --- |
| S1 阻断 | 用户无法完成核心任务，或造成数据/资金损失 | 提交按钮在手机上被键盘遮挡且无法滚动 |
| S2 严重 | 能完成但明显困难、易出错，或可访问性不达 AA | 正文对比度 3.1:1；错误提示不说明原因 |
| S3 一般 | 降低效率或信任感，但有绕行办法 | 术语不一致；次要信息过于显眼 |
| S4 润色 | 视觉细节与打磨 | 图标粗细不一；间距 12/14 混用 |

评估严重度时综合：影响的用户比例 × 发生频率 × 是否可恢复。

## 3. 维度评分（1–5）

- 5：几乎无问题，可作为范例
- 4：少量 S3/S4
- 3：有 S2 或较多 S3
- 2：多处 S2 或存在 S1
- 1：核心任务无法完成

## 4. 可访问性检查项

- 文字对比度：正文 ≥ 4.5:1（AA），大字（≥ 24px 常规或 ≥ 18.66px 粗体）≥ 3:1；AAA 分别为 7:1 与 4.5:1。
- 非文字对比度：输入框边框、图标、焦点指示 ≥ 3:1。
- 触控目标 ≥ 44×44（iOS）/ 48×48 dp（Android）；相邻目标间距足够。
- 焦点可见、Tab 顺序合理、所有交互可键盘操作。
- 图片有替代文本；图标按钮有可读标签。
- 错误、状态不仅靠颜色区分（配合图标或文字）。
- 支持系统字号放大（手机）与 200% 缩放（网页）而不截断。
