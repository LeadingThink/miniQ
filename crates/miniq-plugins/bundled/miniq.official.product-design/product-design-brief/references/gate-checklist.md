# 简报关卡判定清单

## 1. 判定表

| 情况 | 目标 | 用户结果 | 结论 |
| --- | --- | --- | --- |
| “帮我做个健身 App 的首页，让用户一眼看到今天的训练” | 清楚 | 清楚 | 复述默认值，继续 |
| “照这张截图做出来” + 图片 | 清楚（还原该界面） | 清楚（与图一致） | 复述，继续 |
| “把 xxx.com 克隆一份” | 清楚 | 清楚 | 复述，先提醒网站条款，继续 |
| “做一个好看的页面” | 不清楚 | 不清楚 | 提问 |
| “给我们的 SaaS 出几个方向”（user-context 有产品信息） | 清楚（结合上下文） | 基本清楚 | 复述，继续 |
| “给我们的 SaaS 出几个方向”（无任何上下文） | 不清楚是哪个页面 | 不清楚 | 提问 |
| “重新设计我们的设置页，像 Linear 那样” | 清楚 | 需推断：设置页的主要任务 | 能从现有页面截图推断则复述继续，否则问一题 |

## 2. 提问模板（选用，最多 3 题）

1. **目标**：“这次想先做哪个界面/流程？” 选项举例：首页 / 注册登录 / 核心任务流程 / 设置页；默认：首页。
2. **用户结果**：“主要是谁在用，用完要完成什么？” 可给 2–3 个猜测选项。
3. **视觉来源**（仅在影响大时问）：“视觉上有参考吗？” 选项：沿用现有产品 / 参考某个产品 / 让我出几个方向；默认：出几个方向。

不要问：颜色偏好、字体、页数、动画细节、技术栈——这些用默认值或后续迭代解决。

## 3. 默认值表

| 维度 | 默认 |
| --- | --- |
| 平台 | user-context 中的“主要平台”；未知时：消费类 → 手机，工具/后台/SaaS → 桌面 |
| 视口 | 手机 390×844；桌面 1440×1024；有参考图时与参考图一致 |
| 保真度 | 有视觉参考或已选方向 → 高保真；只有文字需求且只要“先看流程” → 灰阶线框 |
| 视觉来源 | 已有产品/代码库 → 沿用其设计系统；有参考产品 → 截图后作为参考；都没有 → 先 ideate |
| 范围 | 1 条主流程、3–5 屏；落地页 1 页 |
| 技术路线 | 见 `product-design-router/references/local-preflight.md` |
| 文案语言 | 跟随用户语言 |
| 数据 | 贴近真实的模拟数据 |

## 4. 复述句要素

一句话包含：**做什么** + **平台/视口** + **视觉来源** +（可选）**范围**。例：
- “我按桌面 1440 宽，沿用你们现有的组件和配色，做‘新建项目 → 邀请成员’这条两屏流程。”
- “这是重设计：我会先截取现在的设置页和 Linear 的设置页，再出三个方向给你挑。”
