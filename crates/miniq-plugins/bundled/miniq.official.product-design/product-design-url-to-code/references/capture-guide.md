# 网页截图指南

## 1. 标准截取序列

| 步骤 | browser_automation 动作 | 说明 |
| --- | --- | --- |
| 1 | `newTab` + `navigate` url | 独立标签，避免影响用户已打开的页面 |
| 2 | `resize` 1440×1024 | 桌面基准视口 |
| 3 | `wait` 1500–3000ms | 等待字体、图片、懒加载 |
| 4 | `snapshot` | 判断是否有 Cookie 弹窗、登录墙、错误信息 |
| 5 | 关闭 Cookie 弹窗（如有） | 只点“拒绝/关闭/仅必要”，不接受额外追踪 |
| 6 | `screenshot` | 首屏，保存为 `desktop-01.png` |
| 7 | `scroll` deltaY≈视口高度 × 0.9 → `wait` → `screenshot` | 依次 `desktop-02.png`…，直到底部 |
| 8 | `resize` 390×844，重复 3–7 | 手机版（如需要），`mobile-01.png`… |

## 2. 失败判定

| 现象 | 判定 | 处理 |
| --- | --- | --- |
| 出现登录/注册表单占据主体 | 登录墙 | 重试一次 → 停止 |
| 404、500、Access Denied、空白页 | 错误页 | 重试一次 → 停止 |
| 验证码、“确认你是人类” | 机器人检测 | 直接停止，不绕过 |
| 最终地址域名与输入不同 | 跳转 | 告知用户实际地址；若为同一品牌的地区站可继续，否则停止 |
| 截图全黑/全白 | 渲染失败 | 等待更久重试一次 → 停止 |

停止时的回复模板：“打开 <网址> 后看到的是 <现象>，没法拿到页面截图，所以先不动手。你可以直接发几张页面截图给我，我照着还原。”

## 3. 拼接与命名

- 每段截图记录 `scrollY`，写入 `design/qa/reference/README.md`，方便 QA 时对应原型相同位置。
- 固定导航（sticky header）会在每段重复出现，实现时只做一次。

## 4. 内容与版权

- 文案：可在本地原型中照搬以便比对；交付说明中提醒上线前替换。
- 图片：默认用 `generate_image` 生成替代图，比例与内容类型一致。
- Logo / 商标：用文字占位，除非用户确认是自己的品牌。
- 字体：商业字体用最接近的开源字体替代。
