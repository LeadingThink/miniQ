# 设计 QA 评分细则

## 1. 严重度定义

| 级别 | 定义 | 是否阻塞交付 |
| --- | --- | --- |
| P0 | 页面无法打开、白屏、核心路径断开、报错；截图与参考明显不是同一界面 | 阻塞 |
| P1 | 与参考的结构性差异：区块缺失/顺序错、布局方向错、主色错、主要文案错；核心交互（导航、提交、Tab）不可用；手机视口出现横向滚动或内容被遮挡 | 阻塞 |
| P2 | 明显可见的细节差异：间距偏差 > 8px、字号/字重层级错、圆角/阴影明显不同、图片比例错或拉伸、缺少 hover/focus/加载/空/成功态之一、正文对比度不达 AA、文字截断 | 阻塞 |
| P3 | 需要仔细看才发现：间距偏差 ≤ 8px、颜色轻微偏差、图标形状略不同、字体替代导致的字形差异、动效细节 | 不阻塞，列为后续 |

判定原则：用户第一眼能看出差异 → 至少 P2；影响完成任务 → 至少 P1。

## 2. 七个比对维度

| 维度 | 检查项 |
| --- | --- |
| 布局与间距 | 区块顺序与数量、栅格与边距、对齐、元素尺寸、间距节奏 |
| 排版 | 字族气质、字号层级、字重、行高、换行位置、截断 |
| 颜色与视觉 | 背景/表面/主色/文字色、边框、圆角、阴影、分割线 |
| 资产 | 图片内容类型与构图、比例、清晰度、图标风格；无占位、无 emoji/CSS 伪造 |
| 文案 | 与参考逐字一致（还原类）或符合产品语境（原型类）；无 lorem ipsum |
| 交互与状态 | 导航、返回、Tab、表单校验/提交、加载/空/错误/成功、hover/focus/active |
| 响应式与可访问性 | 目标视口无溢出、触控目标 ≥ 44px、焦点可见、对比度（可用 `../../product-design-review/scripts/contrast.py`） |

## 3. 维度打分（1–5）

- 5：无差异或仅极少 P3
- 4：只有 P3
- 3：有 1–2 个 P2
- 2：多个 P2 或有 P1
- 1：有 P0

通过条件：所有 P0–P2 已修复（`final result: passed`）。评分用于沟通质量，不替代通过条件。

## 4. 比对方法

1. 同视口：参考图的 CSS 视口 = 截图视口。
2. 同状态：同一屏、同一 Tab、同样的数据、同样的滚动位置、无 hover。
3. 同批查看：参考图与截图在同一次 `view_image` 调用中查看。
4. 先整体后局部：先看区块结构（P0/P1），再逐区块看细节（P2/P3）。
5. 描述差异时写“参考：…；实现：…”，避免“有点不一样”。

## 5. 问题描述示例

| 严重度 | 屏幕/视口 | 问题 |
| --- | --- | --- |
| P1 | 首页@390x844 | 参考：顶部为搜索框 + 分类横滑；实现：缺少分类横滑 |
| P2 | 详情@390x844 | 参考：主按钮高 52、圆角 26（胶囊）；实现：高 44、圆角 10 |
| P2 | 登录@390x844 | 提交空表单无错误提示 |
| P3 | 首页@1440x1024 | 参考卡片阴影略柔和；实现阴影偏深 |

## 6. 受阻（blocked）

以下情况写 `final result: blocked` 并停止：截图工具不可用、原型无法启动且重试失败、参考图缺失且无屏幕清单。受阻原因要写清缺什么、用户能做什么。
