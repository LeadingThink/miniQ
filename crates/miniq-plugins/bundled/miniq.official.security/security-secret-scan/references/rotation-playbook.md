# 凭据泄露处置手册

原则：**只要凭据可能被他人读到，就先轮换，再清理。** 清理 git 历史不能让已经被复制、缓存、fork 的凭据失效。

## 1. 处置顺序

1. **确认影响面**（不联网验证凭据）：类型、权限范围、所属环境、暴露面（公开/内部/本地）、首次引入提交与时间（`git log --all -S '<前缀>' --format='%h %ad %an' --date=short`）。
2. **吊销/轮换**：在签发平台生成新凭据 → 更新所有使用方（密钥管理、CI 变量、部署环境）→ 吊销旧凭据。对无法立即轮换的，至少缩小权限或加来源限制。
3. **审计滥用**：查看签发平台的访问日志（从泄露时间点至今）：异常 IP、异常调用量、新建资源、新签发的凭据。
4. **代码改造**：把值移到环境变量、密钥管理服务或运行时注入；提交 `.env.example` 仅含键名；把敏感文件加入 `.gitignore`。
5. **历史清理**（可选，需要用户同意）：见第 3 节。
6. **预防**：加 pre-commit 或 CI 检查（第 4 节），更新基线。
7. **记录**：在事件记录或 `security-track-findings` 登记，写明时间线与负责人。

## 2. 常见平台的轮换要点

| 类型 | 轮换要点 | 滥用排查 |
| --- | --- | --- |
| AWS 访问密钥 | IAM 为该用户新建密钥 → 更新使用方 → 停用旧密钥观察 → 删除；优先改用角色/临时凭据 | CloudTrail 按访问密钥 ID 检索 |
| GitHub/GitLab 令牌 | 在设置中撤销；改用细粒度、最短有效期、最小仓库范围的令牌或 App | 组织审计日志 |
| 云厂商 AccessKey（阿里云、腾讯云等） | 控制台新建 → 替换 → 禁用 → 删除；优先 RAM 角色 / STS | 操作审计 |
| 数据库口令 | 修改口令或新建账号并收回旧账号；检查是否对公网开放 | 数据库审计日志、连接来源 |
| 私钥（TLS、SSH、签名） | 生成新密钥对；TLS 需重签并吊销证书；SSH 从 `authorized_keys` 删除旧公钥；签名密钥需评估已签发产物 | 证书透明日志、登录日志 |
| 包发布令牌（npm、PyPI） | 立即撤销；检查近期发布版本是否异常；启用 2FA 与可信发布 | 包版本历史 |
| JWT 签名密钥 | 更换密钥会使所有会话失效，需安排窗口；支持多密钥（`kid`）平滑轮换 | 异常令牌签发 |
| Webhook（Slack、企业微信等） | 删除并重建 Webhook | 频道异常消息 |
| 支付平台密钥 | 在控制台滚动密钥；使用受限密钥 | 交易与退款记录 |

## 3. 历史清理

仅在以下情况考虑：仓库将要公开、合规要求、敏感文件体积大或含个人信息。

- 工具：`git filter-repo --path <文件> --invert-paths`（删除文件）或 `--replace-text <规则文件>`（替换字符串）；BFG Repo-Cleaner 亦可。
- 影响：所有提交号改变；需要强制推送所有分支和标签；协作者必须重新克隆；开放的 PR、fork、CI 缓存、镜像仓库里仍有旧对象；托管平台可能需要联系支持清理缓存视图。
- 操作前：用 `ask_user` 取得明确同意，备份仓库（`git clone --mirror`），通知协作者。
- 本技能只给出命令与影响说明，**不自行执行**强制推送。

## 4. 预防措施

- pre-commit 钩子：`python3 <插件目录>/security-secret-scan/scripts/scan_secrets.py . --baseline secrets-baseline.json --no-entropy --fail-on-findings`，或使用 gitleaks 的 pre-commit 集成。
- CI：同样命令在 PR 上运行，只对新增指纹失败。
- 平台能力：启用托管平台的推送保护/密钥扫描。
- 工程习惯：`.env` 不入库；示例文件只放键名；测试使用明显的假值（如 `test-not-a-real-key`）；凭据使用短期、最小权限。

## 5. 报告中的处置建议模板

```markdown
### S-01 生产数据库口令（src/config.py:12，`S3cr****`）
- 暴露面：内部仓库，已推送到 main（自 2024-03-02 起，提交 a1b2c3d）
- 立即：在数据库新建账号并更新部署变量 → 收回旧账号
- 排查：检查 2024-03-02 以来的连接来源
- 代码：改为读取环境变量 `DATABASE_URL`，提交 `.env.example`
- 历史：内部仓库，暂不改写历史（原因：已轮换，改写成本高）
- 负责人/期限：待用户指定
```
