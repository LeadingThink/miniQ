# 差异复审检查项

逐项过一遍，每项在 coverage 的 surfaces 中记录结论（`reported` / `no_issue` / `not_applicable`）。

## 新增或修改的入口

- 新路由、RPC 方法、CLI 子命令、消息消费者、定时任务、webhook：是否挂上了与同类入口一致的鉴权与授权？
- 路由参数/请求体新增字段：是否经过校验？是否可被用于越权（例如新增 `user_id`、`tenant_id`、`role` 字段被直接信任）？
- 公开范围变化：内部接口改为外部可访问、CORS 放宽、监听地址从 127.0.0.1 改为 0.0.0.0。

## 安全控制的变化

- 删除或绕过：鉴权装饰器/中间件被移除、`skip_auth`/`permitAll` 类开关、`if debug` 分支、测试专用后门。
- 弱化：校验正则放宽、允许列表扩大、超时/速率限制调高、加密算法或密钥长度降低、TLS 校验关闭。
- 顺序：校验移到使用之后、授权检查在查询之后（TOCTOU）。

## 数据流到危险汇点

- 新出现的：命令执行、动态代码、原生 SQL/NoSQL 拼接、模板原样输出、文件路径拼接、归档解压、反序列化、出站请求（SSRF）、重定向、正则（ReDoS）。
- 已有汇点的新数据来源：原先只接收常量，现在接收用户输入。

## 敏感数据

- 日志、错误信息、分析埋点中新增的令牌、密码、个人信息。
- 新增硬编码密钥或测试凭据（调用 `security-secret-scan` 的脚本扫描差异中的新增行）。
- 响应序列化新增字段导致过度暴露。

## 依赖与构建

- 新依赖：来源可信吗？名字是否疑似仿冒（typosquatting）？是否带安装脚本？
- 版本变化：降级、从固定版本改为范围、移除锁文件。
- CI 工作流：`pull_request_target` + checkout PR 代码、未固定版本的第三方 action、把密钥暴露给不可信代码、`permissions` 扩大。
- 容器与 IaC：以 root 运行、特权模式、公开存储桶、安全组放开。

## 测试

- 删除或跳过了安全相关测试？新功能是否缺少负向测试（未授权访问应被拒绝）？
