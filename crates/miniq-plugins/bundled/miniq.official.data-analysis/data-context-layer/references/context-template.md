# 数据上下文模板

## README.md
```markdown
# <业务域> 数据上下文
- 适用范围：<支持哪些问题>
- 数据源：<库/文件/仓库路径>
- 维护人：<姓名/团队>　最后更新：<YYYY-MM-DD>
## 表清单
| 表 | 粒度 | 主键 | 时间列 | 行数(约) | 刷新 | 文档 |
## 核心指标
| 指标 | 一句话定义 | 文档位置 | 状态(已验证/待确认) |
## 验证记录
| 日期 | 指标 | 文档口径结果 | 对照来源 | 差异 | 结论 |
## 待确认问题
```

## tables/<表名>.md
```markdown
# <表名>
- 粒度：一行 = <...>
- 主键：<列>（唯一性已于 <日期> 验证）
- 时间列：<列>（时区：<...>；含义：创建/更新/业务发生时间）
- 刷新：<频率、延迟>　上游：<来源系统/任务>
## 字段
| 字段 | 类型 | 含义 | 取值/枚举 | 空值率 | 备注 |
## 常见过滤
- 剔除测试：`is_test = 0`
## 已知问题
```

- 时间归属与时区：
- 粒度与可切分维度：
- 常见误用：
- 来源依据：<文档/报表/负责人>　状态：已验证 | 待确认 | 推断
```

## joins.md
| 左表.键 | 右表.键 | 基数 | 命中率 | 注意事项 |

## 项目技能（可选，放在用户技能目录，不放入本插件）
```markdown
---
name: <业务域>-data-context
description: 分析<业务域>数据（<核心表>、<核心指标>）时使用，先读取 data-context/ 中的口径与坑点
---
1. file_read data-context/README.md，确认问题在适用范围内
2. 按需读取 tables/*.md、metrics.md、gotchas.md
3. 优先复用 queries/*.sql；新写查询遵循 metrics.md 口径
4. 发现文档与数据不一致时，更新文档的“待确认问题”并告知用户
```
