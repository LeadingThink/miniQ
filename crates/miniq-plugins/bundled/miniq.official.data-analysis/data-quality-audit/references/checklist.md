# 数据质量检查清单

按维度逐项勾选。每项给出：怎么查（SQL/Python 思路）、常见误判。

## 1. 完整性
- [ ] 每列空值率；把 `""`、`NA`、`N/A`、`null`、`None`、`-`、`0000-00-00`、`1970-01-01` 等占位值也算作缺失
- [ ] 缺失是否集中在某时间段/渠道/版本（按维度切片看缺失率）
- [ ] 期望存在的日期/分区是否齐全（生成完整日历左连接，找空洞）
- [ ] 期望存在的实体是否齐全（维表中存在但事实表中从未出现的实体）
- 误判：可选字段天然为空；新字段上线前的历史记录为空

## 2. 唯一性
- [ ] 主键/组合键重复数与重复率
- [ ] 完全重复行（管道重复加载的典型信号）
- [ ] 标准化后的伪重复：大小写、前后空格、全角半角、繁简体、电话/邮箱格式
- [ ] 同一实体多条“当前”记录（缓慢变化维 SCD 的有效期重叠）
- 误判：事件表本就允许同一用户多条记录——先确认粒度

## 3. 有效性
- [ ] 类型：数字存成文本、千分位逗号、货币符号、百分号、科学计数法
- [ ] 范围：负数金额/数量、超过 100% 的比率、未来日期、年龄 > 120
- [ ] 枚举：出现未定义的状态码、拼写变体
- [ ] 格式：邮箱、手机号、身份证、邮编、ISO 日期、时间戳单位（秒/毫秒）
- [ ] 常量列、几乎全空列、疑似测试数据（test、demo、内部账号）

## 4. 一致性
- [ ] 跨字段逻辑：结束时间 ≥ 开始时间；支付金额 ≤ 订单金额；状态与时间戳匹配
- [ ] 跨表参照完整性：外键在维表中存在；孤儿记录比例
- [ ] 连接放大：一对多连接后求和被重复计算（连接前后行数与总额对比）
- [ ] 跨系统口径：同名指标在不同表/看板中的定义是否一致（时区、去重键、是否含退款/测试）

## 5. 准确性（对账）
- [ ] 行数：源系统 vs 仓库 vs 报表
- [ ] 金额：与财务/账单/上一版报告对账，设定容差（如 ±0.5%）
- [ ] 抽样追踪：挑 3–5 条记录从源头跟到最终结果
- [ ] 可逆推：头条数字 ≈ 分项之和；用户数 × 人均 ≈ 总量

## 6. 时效性
- [ ] 最大时间戳距今多久；是否满足约定的刷新频率
- [ ] 最近 N 天的行数是否明显偏低（延迟到达）
- [ ] 时区：日切点是否一致（UTC vs 本地时间）

## 7. 稳定性 / 漂移
- [ ] 每日行数、关键指标均值、空值率的时间序列突变（均值±3σ 或 中位数±3·MAD）
- [ ] 类别基数突增/突减（新枚举值、ID 格式变化）
- [ ] 分布变化：分位数对比（p50/p90/p99）前后两期
- [ ] 与已知事件对齐：发版、埋点变更、迁移、回填、营销活动、节假日

## 8. 可追溯性
- [ ] 数据来源、生成脚本/任务、负责人、刷新时间是否可查
- [ ] 字段定义是否有文档；与 `data-context-layer` 的语义层一致

## 常用 SQL 片段思路
- 空值率：`SELECT AVG(CASE WHEN col IS NULL OR TRIM(col)='' THEN 1.0 ELSE 0 END) FROM t`
- 主键重复：`SELECT k, COUNT(*) c FROM t GROUP BY k HAVING c > 1 ORDER BY c DESC LIMIT 20`
- 孤儿记录：`SELECT COUNT(*) FROM f LEFT JOIN d ON f.k=d.k WHERE d.k IS NULL`
- 日期空洞：用递归 CTE 生成日历后 LEFT JOIN 按日计数
- 连接放大：分别统计连接前 `SUM(amount)` 与连接后 `SUM(amount)`
