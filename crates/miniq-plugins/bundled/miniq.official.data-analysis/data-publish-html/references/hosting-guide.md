# 托管与部署指引

| 目标 | 适合 | 步骤要点 |
|---|---|---|
| 直接发送文件 | 小范围、一次性 | 发送单文件 HTML；收件人双击用浏览器打开 |
| 公司内网/网盘 | 内部共享 | 上传到共享盘或内网文件服务；确认该服务能以网页形式预览 HTML，否则只能下载后打开 |
| GitHub Pages | 公开或组织内（企业版可私有） | 仓库放 `index.html` → Settings → Pages → 选择分支与目录；或 `gh` CLI 推送 |
| Netlify / Vercel / Cloudflare Pages | 快速公开链接 | 拖拽上传目录，或用各自 CLI 部署静态目录；可设置访问密码（视套餐） |
| 对象存储（S3/OSS/COS） | 企业内静态托管 | 上传 `index.html`，设置 `Content-Type: text/html; charset=utf-8`；配合 CDN 与访问控制 |
| Google Sites | 已使用 Google Workspace | 页面中“嵌入 → 嵌入代码”粘贴 HTML（有大小限制），或上传到 Drive 后链接；复杂页面建议用上面的静态托管后再嵌入链接 |
| 内网 Web 服务器（Nginx 等） | 自有服务器 | 复制到站点目录；配置访问控制 |

## 访问控制提示
- 公开链接等同对外发布：数据须脱敏并获得授权
- 需要登录才能访问时，选择支持身份认证的平台（企业网盘、带 SSO 的内部托管）
- 链接“不公开但可访问”不等于安全

## 更新流程
1. 重跑数据与构建脚本生成新的 HTML
2. 重新打包、检查、预览
3. 覆盖原位置的同名文件（保持链接不变），在页面中更新“数据截至”时间
4. 如需保留历史版本，按日期另存 `report-YYYYMMDD.html`
