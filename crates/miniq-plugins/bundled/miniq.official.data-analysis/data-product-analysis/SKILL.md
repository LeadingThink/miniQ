# 产品与业务分析

## 触发场景
- 漏斗：“注册到付费哪一步流失最多？”
- 留存/同期群：“新用户 30 日留存怎么样，比去年好吗？”
- 分群：“哪类客户最有价值？”RFM、行为分群
- 功能采纳：“新功能上线后有人用吗？对留存有帮助吗？”
- 实验：“这个 A/B 实验能不能全量？”
- 单位经济与定价：CAC、LTV、回收期、毛利、价格弹性
- 渠道/营销：渠道 ROI、归因、投放效果
- 流失：流失率、流失前行为、风险名单（仅聚合汇报）

## 前置条件
- 事件/订单/用户明细数据，至少含 用户 ID、时间、事件或金额；实验需含分组字段
- 明确的问题与决策（上线/停止/加大投入/改价……）
- 方法手册见 `references/analysis-methods.md`；实验评估见 `references/experiments.md`

## 分步流程
1. **问题定型**：把用户问题映射到一种分析类型（上表），写下 决策、成功标准、分析单位（用户/账户/订单/会话）、时间窗。不确定时 `ask_user` 确认决策是什么。
2. **上下文与口径**：用 `data-context-layer`/`data-business-context` 获取事件定义、上线时间、实验设计文档。
3. **数据准备**：`doc_read` 预览，`data-quality-audit` 画像关键表（用户 ID 缺失、事件重复、时间错乱、机器人流量）；确认“一行代表什么”。
4. **计算**：`file_write` 写 `analysis/product/<主题>.py`（或 SQL），`shell_run` 执行。按 `references/analysis-methods.md` 对应小节的方法：
   - 漏斗：严格有序、限定转化窗口，给出每步转化与整体转化，并按渠道/平台分拆
   - 留存：按首次行为日期分同期群，输出留存矩阵与留存曲线；注意右删失（近期群观察期不足）
   - 分群：RFM 分位打分或基于业务规则；每群给出规模、价值占比、特征
   - 实验：先做 SRM 检查，再算效应、置信区间、p 值；见 `references/experiments.md`
   - 单位经济：CAC、ARPU、毛利、留存推导 LTV、回收期
5. **可视化**：`data-visualize`（漏斗图、留存热力图、同期群曲线、分群气泡图、实验效应带置信区间的点图）。用 `view_image` 检查。
6. **解读与建议**：每条结论写 数字 + 对比基准 + 样本量 + 置信程度 + 建议行动。区分相关与因果（非实验数据的“使用某功能的用户留存更高”多半有选择偏差）。
7. **校验**：关键数字复算；过 `data-validate-analysis` 快速清单（尤其是选择偏差、多重比较、小样本）。
8. **交付**：`analysis/product/<主题>-report.md`，需要时经 `data-report` 渲染或 `data-dashboard` 做成看板。

## 工具与参数要点

- `file_glob`/`doc_read`：确认事件表、用户表、订单表和实验分组表的字段与粒度
- `shell_run`：用 Python 或 SQL 计算漏斗、留存 cohort、分群、A/B 显著性，把脚本保存在 `analysis/product/`，便于复跑。pandas 缺失时用 csv 和 collections 实现
- 先用 `<插件目录>/data-quality-audit/scripts/profile_data.py <文件> --key <用户ID> --date-col <时间>` 检查重复事件和时间范围
- 图表：漏斗图、留存热力图、分群柱状图用 `<插件目录>/data-visualize/scripts/make_chart.py`（funnel/heatmap/bar）生成，再用 `view_image` 逐张检查
- `file_write`：输出 `analysis/product/report.md`。实验结论必须包含样本量、效应量和置信区间
- `ask_user`：分析单位、时间窗、实验的主要指标不明确时再确认

## 质量检查
- 分析单位一致（不混用用户数与会话数）
- 漏斗与留存的时间窗、事件定义写明；近期同期群的不完整观察已标注
- 实验：SRM、样本量/检验力、预设主指标、护栏指标、多重比较
- 每个建议都能对应到一条证据
- 分群结果只呈现聚合，不输出个人明细

## 失败回退
- 缺用户 ID：只能做会话/订单级分析，说明无法计算留存
- 实验无随机化或 SRM 失败：不下因果结论，改为描述性对比并建议重做实验
- 样本量不足：报告区间而非点估计，给出达到检验力所需样本量
- 缺成本数据：单位经济只给收入侧，列出需要的成本字段

## 交付格式
```markdown
# <主题>分析
## 结论与建议（先给答案）
## 问题与决策、分析单位、时间窗
## 数据与口径
## 结果（按问题分节，每节：图 + 关键数字 + 解读）
## 方法与局限（偏差、样本量、未验证假设）
## 下一步（实验、埋点、监控）
```
