# Notebook 结构规范

## 推荐单元格顺序
1. **标题（Markdown）**：分析目标、数据来源、作者、日期
2. **环境与导入（Code）**：import、显示设置、打印关键库版本
3. **参数（Code，唯一）**：数据路径、时间窗、阈值、随机种子；可加 `parameters` 标签以便 papermill 参数化
4. **数据加载（Code）**：读取、打印形状与字段类型
5. **数据检查与清洗**：缺失、重复、异常处理，每步说明理由
6. **分析章节**：每节 = Markdown 小标题（问题）→ Code → Markdown 解读（结论）
7. **结论（Markdown）**：关键发现、局限、下一步
8. **导出（Code，可选）**：保存图表与结果到 `analysis/`

## 编码约定
- 单元格短小，只做一件事；可复用逻辑提炼为函数
- 不依赖执行顺序之外的状态；避免在后面的单元格修改前面的变量
- 图表调用 `plt.show()` 或保存文件；中文字体设置放环境单元格
- 大表只显示 `head()`/汇总，避免 notebook 体积膨胀

## 脚本 → Notebook
- 以 `# %%` 分段（VS Code/Jupytext 约定），`# %% [markdown]` 表示 Markdown 单元格
- 函数定义与主流程分开；主流程拆为若干单元格

## 版本管理
- 提交前清空输出，或另存执行版为 HTML
- 可选 jupytext 双格式（.ipynb + .py）便于代码评审
