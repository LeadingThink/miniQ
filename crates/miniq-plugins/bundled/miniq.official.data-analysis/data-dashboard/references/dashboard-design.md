# 看板设计原则

## 信息层级
1. **KPI 带**（顶部）：4–6 个卡片，每个含 当前值、对比变化（带方向色）、目标进度、迷你趋势
2. **主图**：最重要指标的趋势，含目标线/去年同期线
3. **拆分区**：按 2–3 个关键维度的对比（排序条形、堆叠）
4. **明细区**：可排序表格，Top N + 搜索
5. **说明区**：口径、数据截至时间、已知问题、联系人

## 看板类型
| 类型 | 目的 | 特点 |
|---|---|---|
| 战略/高管 | 看大盘、看目标 | 指标少、周/月粒度、强调对比与目标 |
| 运营/监控 | 发现异常、及时处理 | 日/小时粒度、阈值告警色、最近 N 天 |
| 分析/探索 | 自助下钻 | 筛选多、维度多、明细可导出 |

## 设计规则
- 一个看板服务一类受众与一组问题；避免“什么都放”
- 从左上到右下重要性递减
- 同一指标在不同图中颜色一致；状态色只用于表达好坏
- 所有图的时间范围一致，或明确标注
- 数字统一格式与单位，KPI 卡片最多保留 3 位有效数字
- 空状态与异常状态有提示（无数据、数据延迟）
- 移动端：卡片单列堆叠，图表宽度 100%

## 筛选器
- 全局筛选（时间、地区）放顶部并显示当前选择
- 筛选影响范围要明确；不支持被筛选的区块应标注
- 静态 HTML 的筛选依赖内嵌的预聚合数据，维度组合过多时限制可选维度

## 看板评审清单
- [ ] 第一屏回答核心问题
- [ ] 每个 KPI：口径、对比、方向、目标
- [ ] 截至时间与来源
- [ ] 抽查 3 个数字与源数据一致
- [ ] 筛选交互正常
- [ ] 窄屏可读
- [ ] 无外部依赖（单文件 HTML）
