# 分析结论校验（交付前复核）

以“挑刺的审稿人”身份复核一份已有分析。目标不是重做分析，而是找出会让结论出错或误导的问题，并判断能否分享。

## 触发场景
- “帮我检查一下这份分析/报告/看板有没有问题”“这个结论站得住吗”
- 本插件其他技能产出交付物后的最后一道关
- 同事的 Notebook、SQL、Excel 模型、PPT 需要复核

不适用：检查原始数据本身的质量 → `data-quality-audit`。

## 前置条件
- 被审对象：报告（md/html/pdf/docx/pptx）、Notebook、SQL、脚本、表格、看板截图或 HTML
- 最好能访问底层数据或查询，以便复算；不能访问时评级上限为“附带说明后分享”
- 详细清单见 `references/validation-checklist.md`，统计陷阱见 `references/pitfalls.md`

## 分步流程
1. **收集材料**：`doc_read` 读报告/PDF/Office；`file_read` 读脚本、SQL、`.ipynb`；HTML 看板用 `browser_automation` 打开 `file://` 路径截图，或 `view_pdf` / `view_image` 看渲染结果。
2. **还原问题**：一句话写出分析要回答的问题、决策、受众；列出所有“头条结论”（数字 + 主张）。
3. **方法复核**：问题与方法是否匹配、总体与样本、时间窗与对比基准、指标口径（分子/分母/去重/时区/过滤）、分群定义是否基于结果变量（选择偏差）。
4. **数据复核**：来源与截至日期、连接是否放大、过滤是否遗漏、不完整周期、测试数据、缺失处理。必要时调用 `data-quality-audit` 的画像脚本快速检查。
5. **计算抽查**（至少挑 3 个关键数字）：`file_write` 写 `analysis/validate/recompute.py`，`shell_run` 执行，从原始分子分母复算；做一次“小切片”检查（单日/单实体）；可逆推的头条数字做逆推；对账到可信来源（财务、上一版报告）。
6. **合理性**：数量级、增长率、占比之和是否 100%、与行业常识/历史区间是否一致；结论出乎意料时要求第二条独立路径复算。
7. **统计陷阱**：逐条过 `references/pitfalls.md`（辛普森悖论、均值的均值、幸存者偏差、多重比较、小样本、回归均值、挑选时间窗、前视偏差、相关≠因果）。
8. **图表复核**：柱状图从 0 起、轴单位与时间范围标注、刻度一致、双轴与截断轴是否有理由、标题是否超出数据所能支持的范围、颜色语义一致；以最终渲染形态检查，而不只看源码。
9. **评级与输出**：写 `analysis/validate/validation-report.md`（模板见下）。能直接修的小问题（错别字、口径说明缺失）在征得同意后用 `file_edit` 修；重大问题只报告不擅改。

## 工具与参数要点

- `file_read`/`doc_read`：读取被审对象（md/docx/pdf/pptx/xlsx）。`view_pdf`/`view_image`：检查图表与版式，以实际像素为准，不凭文字推断
- `browser_automation`：打开 HTML 报告或看板，截图后核对数字、筛选和交互
- `shell_run`：用原始数据独立复算关键数字，把复算脚本写到 `analysis/validate/`。复算不能照搬被审脚本的逻辑
- 复算可借用 `<插件目录>/data-metric-diagnostics/scripts/decompose_change.py`（拆解变化）和 `<插件目录>/data-kpi-reporting/scripts/kpi_scorecard.py`（指标、达成率、环比），作为独立的交叉验证
- `file_grep`：检查口径词、时间窗和单位是否前后一致，例如 `同比|环比|去重|口径`
- `file_write`：输出 `analysis/validate/report.md`，评级只能取“可直接分享 / 附带说明后分享 / 需要修订”之一

## 质量检查
- 每个问题都有证据与影响说明，并按“对决策的影响”排序，而不是按文档顺序
- 复算结果要写明 已验证 / 有差异（差多少）/ 未验证（原因）
- 区分：必须修（阻断分享）、应当补充的说明、可选改进

## 失败回退
- 无法访问底层数据：只做方法、逻辑、内部一致性（数字之间能否互相推出）与图表检查，并在评级中说明
- 文件格式无法读取：请用户导出为 PDF/Markdown/CSV
- 分析过长：先审头条结论和支撑它们的计算，其他部分抽查并说明覆盖范围

## 交付格式
```markdown
## 校验报告：<分析名称>
### 总体评级：可直接分享 | 附带说明后分享 | 需要修订
一句话理由

### 方法复核
### 发现的问题
1. [高/中/低] 问题 — 证据 — 影响 — 建议
### 计算抽查
- <指标/结论>：已验证 / 有差异（原值 X，复算 Y）/ 未验证（原因）
### 图表复核
### 建议改进
### 分享时必须附带的说明
### 交付阻断项（如有）
```
评级标准：
- 可直接分享：方法合理，关键数字已验证或风险低，说明清楚，只剩小问题
- 附带说明后分享：方向可用，但有明确的假设、局限或未验证项必须告知读者
- 需要修订：存在实质错误、无依据的结论或缺失关键检查
