# 等等，没听懂

## 适用场景
- "等等，你刚才那段我没跟上。"
- "重新解释一下，说人话。"
- "你说的 X 是什么意思？"

## 前置条件
- 若工作区有 `GLOSSARY.md`/`术语表.md`，先 `file_read`，用里面的定义和命名。
- 读 `ste-writing` 技能的原则（简明技术英语的中文版规则）。

## 步骤
1. **停**：不要继续执行上一条回复里的任何计划。
2. **定位断点**：判断用户没听懂的是哪一层：
   - 缺背景（不知道为什么要做这件事）
   - 缺术语（某个词没解释）
   - 缺因果（步骤之间的关系没讲）
   - 缺结论（讲了很多，没说"所以呢"）
   不确定时，`ask_user` 一个问题："是哪一部分没跟上：背景 / 术语 / 步骤 / 结论？"
3. **重讲**，固定结构：
   ```
   **一句话结论**：…

   **背景**（2–3 句）：我们现在在做 X。遇到了 Y。所以要 Z。

   **关键词**：
   - 术语 A：定义（来自术语表 / 本次临时定义）
   - 术语 B：…

   **步骤**（如有）：
   1. 做什么 → 为什么
   2. …

   **接下来需要你**：确认 / 选择 / 什么都不用做
   ```
4. **写法**：一句一个意思；主动语态；不用比喻；中文不超过 25 字一句；不用"赋能/抓手/闭环"类空词；一个概念只用一个名字。
5. 如果用户之后说"懂了，继续"，恢复上一条回复的计划；否则再问。

## 注意事项 / 安全
- 不要为上一条回复道歉或解释"我刚才的意思其实是"，直接重讲。
- 不要引入新的内容；重讲的范围不超过上一条回复。

## 如何确认完成
用户回复"懂了"或继续推进下一步。
