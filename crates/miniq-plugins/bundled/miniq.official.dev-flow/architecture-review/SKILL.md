# 架构深化评审

目标：把**浅模块**变成**深模块**（小接口后面藏大量行为），提升可测性与 AI 可导航性。

## 适用场景
- "改一个功能要碰十个文件，帮我看看怎么办。"
- "新同事/agent 看不懂代码库结构，哪里该收敛？"
- "每隔几天跑一次架构体检。"

## 词汇（全程只用这些词，不混用"组件/服务/API/边界"）
- **模块**：一个有接口的代码单元。**接口**：调用方需要知道的全部。**深度**：接口简单程度 ÷ 实现承载量。
- **缝**：可以在不改两侧的前提下替换一侧的位置。**适配器**：缝上的翻译层；一个适配器 = 假想的缝，两个 = 真实的缝。
- **杠杆**：改一处、影响多处。**局部性**：理解一件事所需读的文件数。
- **删除测试**：删掉这个模块，复杂度是被集中了还是只是搬了家？"集中"就是要找的信号。
- **接口即测试面**：只通过接口测，不测内部。

## 前置条件
- 读 `GLOSSARY.md`（存在时）与 `docs/adr/`：术语表给缝命名，ADR 记录不该再翻的决定。
- 读 `miniq.official.visual-language/visual-language-core/SKILL.md` 与 `references/tokens.md`：报告用统一视觉语言。

## 步骤

### 1. 探索（先定范围，YAGNI）
- 用户点了方向（模块、子系统、痛点）→ 直接看那里。
- 没点 → `shell_run`：`git log --oneline --since='90 days ago' --name-only | sort | uniq -c | sort -rn | head -40` 找热点文件，热点优先；没有明显热点就放宽。
- 用 `agent_run` 起一个子代理有机地走代码库（不要机械打分），记录"摩擦点"：
  - 理解一个概念要在多少个小模块间来回跳？
  - 哪些模块接口和实现一样复杂（浅）？
  - 哪些纯函数只是为了可测被抽出来，真 bug 却藏在调用方式里（无局部性）？
  - 哪些紧耦合模块越过缝互相泄漏？
  - 哪些部分没测试、或透过当前接口难测？
- 对每个疑似浅模块做**删除测试**。

### 2. 产出 HTML 报告
- 写到系统临时目录 `<tmp>/架构评审-<YYYYMMDD-HHmm>.html`（`$TMPDIR`→`/tmp`→`%TEMP%`），**不进仓库**。
- 样式：内联 `tokens.md` 的 CSS；主色黛蓝；禁止 Tailwind/外链 CSS。图：关系是图状（调用图、依赖、时序）用 Mermaid（CDN `https://cdn.jsdelivr.net/npm/mermaid@11.4.1/dist/mermaid.esm.min.mjs`）；"质量块"、"切面"、"收敛动画"等编辑感视觉用手写 div/SVG。
- 每个候选一张卡片：
  - **涉及文件**
  - **问题**：当前架构为何产生摩擦（用术语表的领域词 + 上面的架构词）
  - **方案**：白话说会变成什么
  - **收益**：用局部性与杠杆解释，测试会怎样变好
  - **前 / 后 对比图**：左右并排，自绘，画出"浅"与"深"
  - **推荐强度**徽章：`强烈` / `值得探索` / `试探性`
  - 与 ADR 冲突的候选：只在摩擦足够真实时列出，并加警示："与 ADR-0007 冲突，但值得重开因为……"
- 结尾 **首选推荐**：先做哪个、为什么。
- 用 `shell_run`（后台）`python3 -m http.server` + `browser_automation` 截图，`view_image` 自检（中文、对齐、图是否渲染）。然后 `shell_run open <路径>`（macOS）/ `xdg-open` / `start` 打开给用户，并告知绝对路径。
- **此时不要提接口设计。** `ask_user`："想深入哪一项？"

### 3. 追问循环
用户选定后，用 `grill-me` 走决策树：约束、依赖、深化后的模块形状、缝后面放什么、哪些测试能活下来。
决策落地时顺手做：
- 新模块名对应的概念不在 `GLOSSARY.md` → `file_edit` 追加（文件不存在则创建）。
- 对话中磨尖了一个模糊术语 → 当场更新术语表。
- 用户以承重理由否决某候选 → 提议写 ADR："要不要记成 ADR，免得以后评审再提？"只在理由对未来探索者有用时提；"现在没空"这类不记。
- 想比较深化模块的多种接口 → 用 `agent_run` 并行"设计两次"，每个子代理独立给一版接口与取舍。

## 注意事项 / 安全
- 本技能只产出报告与对齐结论，不改代码。实施交给 `writing-plans` + `test-driven-development`。
- 报告写到临时目录；用户要归档时再复制到 `评审/`。

## 如何确认完成
HTML 报告已生成并截图自检通过；用户选定了一项并完成追问；术语表/ADR 的副作用已落地。
