# 议题分诊

## 适用场景
- "GitHub 上积了 30 个 issue，帮我看看哪些要紧。"
- "TAPD 里这个需求能不能直接交给 agent？"
- "外部提了个 PR，帮我分诊一下。"

**PR 就是带代码的 issue**：同一套角色、状态、流程，只多一步"核对 diff 是否做到了它声称的事"。

## 前置条件
- 议题来源之一可用：GitHub（`gh` CLI 或 `github` MCP）、TAPD（`tapd` MCP）、Linear（`linear` MCP）、飞书多维表格 / 本地 Markdown。首次使用先 `ask_user` 确认用哪个，并记到 `memory_write`。
- 标签映射：下面是**规范角色名**，实际标签字符串可能不同。首次使用 `ask_user` 确认映射并 `memory_write`。
- 所有发到议题系统的评论**必须**以这行开头：
  ```
  > *本评论由 AI 在分诊过程中生成。*
  ```

## 角色
两个**分类角色**：`bug`（坏了）、`enhancement`（新功能/改进）。
五个**状态角色**：`needs-triage`（待评估）、`needs-info`（等报告人补充）、`ready-for-agent`（规格完整，可无人值守交给 agent）、`ready-for-human`（需人实现）、`wontfix`（不做）。
每个已分诊议题恰有一个分类 + 一个状态。状态冲突时先问维护者。
转移：未标注 → `needs-triage` → {`needs-info`, `ready-for-agent`, `ready-for-human`, `wontfix`}；`needs-info` 在报告人回复后回到 `needs-triage`。异常转移先问。

## 步骤

### A. "看看哪些需要我处理"
查询议题系统，按最旧优先分三桶：① 未标注；② `needs-triage`；③ `needs-info` 且上次分诊后报告人有新动态。PR 在范围内时一并列出并标 `[PR]`/`[issue]`；自动发现只看**外部**PR，协作者自己的 PR 不算分诊工作。每条一行摘要 + 计数，让维护者挑。

### B. 分诊具体一条
1. **收集**：读全文（正文、评论、标签、作者、日期；PR 还要 diff）。读之前的分诊笔记，不重复问已解决的问题。按 `GLOSSARY.md` 探索代码库，尊重相关 ADR。做两项检查并报告在哪里查过：(a) **冗余**：按领域概念（不只按字面）搜是否已实现 → 已实现则走 `wontfix`；(b) **既往拒绝**：读 `.out-of-scope/*.md`，找相似的被拒请求。
2. **建议**：告诉维护者你推荐的分类与状态及理由，附与请求相关的代码库摘要。`ask_user` 等指示。
3. **验证声明**：bug → 按报告人步骤复现；PR → 检出、跑相关测试。报告：已确认（给代码路径）/ 失败 / 信息不足（强 `needs-info` 信号）。
4. **追问（按需）**：请求不够清晰时，用 `grill-me` 一轮轮问清，顺手更新 `GLOSSARY.md`/ADR。
5. **落地结果**：
   - `ready-for-agent`：发 agent 简报评论（结构见下）。
   - `ready-for-human`：同简报结构，另注明为何不能委托（判断题、外部权限、设计决定、手工测试）。
   - `needs-info`：发分诊笔记（模板见下）。
   - `wontfix`：**已实现** → 指出位置后关闭，不写 `.out-of-scope/`；**拒绝 bug** → 礼貌解释后关闭；**拒绝 enhancement** → 写 `.out-of-scope/<slug>.md`（请求摘要、拒绝理由、日期、链接），评论里链到它，再关闭。
   - `needs-triage`：打标签；有部分进展可留评论。

### C. 快速改状态
维护者说"把 #42 改成 ready-for-agent"：信任他，`ask_user` 确认要做的动作（改标签、评论、关闭），然后执行。跳过追问。没经过追问就进 `ready-for-agent` 时，问是否要写简报。

## agent 简报结构（发到议题评论）
```
> *本评论由 AI 在分诊过程中生成。*
## Agent 简报
**目标**：一句话。
**验收标准**：可勾选列表，每条可自动验证。
**范围内 / 范围外**：
**相关代码**：文件路径 + 一句话说明。
**已确认事实**：复现结果、现有行为。
**待决策**：无（有则不应进 ready-for-agent）。
**建议技能**：test-driven-development、…
```

## needs-info 模板
```
> *本评论由 AI 在分诊过程中生成。*
## 分诊笔记
**目前已确认：**
- …
**还需要你（@报告人）提供：**
- 具体可操作的问题 1
- 问题 2
```

## 注意事项 / 安全
- 改标签、评论、关闭都是对外可见操作，每次先 `ask_user` 确认。
- 不在评论里暴露内部路径、密钥或未公开计划。
- 恢复之前的分诊会话时，先读旧笔记，核对报告人是否已回答，再呈现更新后的全貌。

## 如何确认完成
目标议题带且仅带一个分类 + 一个状态；对应评论已发出；`wontfix` 的拒绝原因已归档（如适用）。
