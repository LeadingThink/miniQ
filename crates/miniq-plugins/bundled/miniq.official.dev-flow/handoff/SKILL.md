# 会话交接文档

## 适用场景
- "上下文快满了，帮我写个交接。"
- "这个任务明天让另一个同事接手，整理一下。"
- "把进度存下来，我换台电脑继续。"
- 用户给了附加说明（如"下个会话主要做测试"）时，按该说明组织重点。

## 前置条件
- 用 `git_status` 和 `git_diff` 看清当前未提交的改动。
- 用 `file_glob` 找本会话产生的产物（计划、报告、脚本）。

## 步骤
1. **定落点**：默认写到系统临时目录 `$TMPDIR`（无则 `/tmp`；Windows 为 `%TEMP%`）下的 `miniq-handoff-<YYYYMMDD-HHmm>.md`，**不放进工作区**，避免污染仓库。用户明确要求放工作区时，放 `交接/` 目录。
2. **写文档**（`file_write`），结构固定：
   ```markdown
   # 交接：<任务一句话>
   写于 <YYYY-MM-DD HH:mm>｜工作区 <绝对路径>｜分支 <git 分支>

   ## 目标与边界
   做什么、不做什么、验收标准。

   ## 当前状态
   - 已完成：…（引用文件路径/提交号，不复述内容）
   - 进行中：…（卡在哪一步、最后一次观察到的结果）
   - 未开始：…

   ## 关键决定（为什么这样做）
   每条一行：决定 → 理由 → 出处（对话/ADR/issue 链接）。

   ## 已知坑与未解问题
   复现命令、错误原文（脱敏）、尝试过的办法。

   ## 下一步（按顺序）
   1. …
   2. …

   ## 建议加载的技能
   列出下个会话应读的 miniQ 技能名，并说明为什么。

   ## 相关产物
   文件路径、提交、PR/issue 链接。只给引用，不复制内容。
   ```
3. **去重**：规格、计划、ADR、issue、commit、diff 已经记录的内容只引用路径或链接，不复制。
4. **脱敏**：API key、密码、token、手机号、身份证号、内网地址一律替换为 `<已脱敏>`。写完后 `file_grep` 搜一遍 `sk-|token|password|密码|secret` 自检。
5. **回复**：给出文档绝对路径，并用 3 行以内复述"下一步第一件事"。

## 注意事项 / 安全
- 不在交接文档里写对用户或同事的评价。
- 不推测未验证的结论；不确定的标"待确认"。
- 文档语言跟随用户；代码、命令、路径保持原文。

## 如何确认完成
文档已写入指定路径；脱敏自检无命中；"下一步"第一条可以不看对话历史直接执行。
