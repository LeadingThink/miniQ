# 录制证据模型与脱敏规则

## 目录结构
```
~/Movies/miniq-recordings/20250618-150102/
  session.json    {"startedAt","endedAt","endReason","interval","maxMinutes","frames","frameCount","pid"}
  events.jsonl    每行一个事件
  frames/00000.jpg …
```
`endReason` 的取值：
- `user_stopped`：正常结束。
- `cancelled`：用户放弃，不生成技能。
- `timeout`：到达时长上限，需要确认用户是否已经演示完整。

## 事件类型（events.jsonl）
| type | 字段 | 含义 |
|---|---|---|
| start / end | reason | 录制开始、结束 |
| focus | app, window | 前台应用或窗口标题发生变化 |
| frame | file, app | 一张定时截图 |
| note | text | 用户口述或补充说明（`mark` 写入） |
| error | message, detail | 例如截图失败、缺少权限 |

## 分析方法
1. **先看事件，再看图**：用 focus 事件把录制切成若干段，每段对应一个应用内的子任务。
2. 每段只看首帧、末帧，以及中间变化明显的帧。比较相邻帧的差异，写出“做了什么”：
   - `+` 新出现的元素，例如弹窗、新行、提示条。
   - `-` 消失的元素。
   - `~` 发生变化的值，例如输入框内容、开关状态、选中项。
3. 推断意图时，以用户的口述（note）为准，截图用于核对。两者矛盾时问用户。
4. 录制中的误操作和重复尝试（点错后撤销、来回切换）不写入技能。
5. 截图看不清时，可以请用户补一句说明，比猜测要好。

## 参数化规则
| 录制中看到的 | 写进技能时 |
|---|---|
| 具体日期“2025-06-18” | `{日期}`，并注明默认值（如“今天”） |
| 联系人、客户名、邮箱 | `{收件人}` 等参数，运行时询问或从输入读取 |
| 文件路径 | `{文件}`；同时写明“若不存在则询问” |
| 固定的菜单项或按钮文字 | 保留原文，作为常量 |
| 账户名、组织名 | 视情况处理：可以作为常量，也可以作为参数；拿不准就问用户 |

## 脱敏（必须遵守）
- **绝不写入**：
  - 密码、验证码、令牌、API Key。
  - 银行卡号、身份证号。
  - 截图里的私人消息内容。
- 截图中出现上述内容时，用 `[已隐去]` 描述，例如“在密码框输入 [已隐去]”。
- 需要凭据的步骤统一写成：“若需登录，请用户自行完成”。
- `validate_skill.py` 会拦截常见的机密格式，并对手机号、邮箱发出警告。但它不能替代人工检查。

## 能力边界
- 目前是定时截图加前台应用切换记录，**没有**逐次点击或按键的事件流。操作细节要靠截图对比和用户口述来补全。
- 截图间隔 2 秒时，快速的连续点击可能会漏掉。遇到这种情况，可以请用户放慢速度，或者边做边说。
