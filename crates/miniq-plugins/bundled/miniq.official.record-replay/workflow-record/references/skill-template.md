# 生成技能的模板

把 `<…>` 替换为实际内容，章节标题保持不变（`validate_skill.py` 会检查这些标题）。

```markdown
---
name: <小写-连字符-名称>
description: <一句话：什么时候用这个技能，≤200 字>
version: 1
---

# <技能标题>

## 适用场景
- 触发说法：“<用户可能怎么说>”
- 不适用：<边界>

## 输入参数
| 参数 | 含义 | 默认值 | 缺失时 |
|---|---|---|---|
| {日期} | 报表日期 | 今天 | 使用默认值 |
| {收件人} | 发送对象 | — | 询问用户 |

## 前置条件
- 应用：<应用名>，已登录 <账户类型>（未登录时请用户自行登录）
- 权限：辅助功能 / 自动化 / 屏幕录制

## 步骤
1. <动作，按控件名称或文字描述，如“点击工具栏的‘导出’按钮”>
   - 首选路线：<osascript / CLI / 快捷键>；备选路线：app_automation
   - 验证：<看到什么算成功，如“出现‘导出完成’提示”>
2. …

## 成功标准
- <最终可核对的结果，如“~/Downloads 出现 {日期}-报表.xlsx”>

## 需确认的动作
- 第 <n> 步 <发送 / 删除 / 提交>：执行前向用户确认 <具体内容>

## 失败处理
- <常见偏差>：<处理方式>；无法处理时停止并报告当前所在步骤
```

## 写作要点
- 每一步只写一个动作，并附上验证方式。
- 用“意图 + 控件文字”描述，不写坐标、像素或窗口位置。
- 能用脚本、快捷键、API 完成的，写成首选路线。
- 写操作，以及对外发送的内容，都标记为需确认。
