# 中文信息图

## 适用场景
- 用户原话示例：
  - "把这篇文章的要点做成一张信息图，发公众号用。"
  - "这 5 个数据做成一张图，小红书尺寸。"
  - "把我们的服务流程画成一张步骤图，发朋友圈。"
  - "两个方案对比做一张图，领导一眼能看懂。"
- 输入：文章链接或文本、数据表、口头描述的概念。输出：单文件 HTML + PNG。
- 不适用：需要悬停/筛选的交互图表（`visual-charts`）、以插画为主的海报（`poster-cn`）、多页演示（`web-deck-cn`）。

## 前置条件
1. 先读 `../visual-language-core/SKILL.md` 与 `../visual-language-core/references/tokens.md`，令牌 CSS 内联进 HTML。
2. 需要模板 HTML 骨架时读 `references/templates.md`。
3. 读输入：网页用 `web_fetch`；`.md/.txt` 用 `file_read`；`.xlsx/.csv/.docx/.pdf` 用 `doc_read`。
4. `browser_automation` 不支持 `file://`，截图前必须起本地 http 服务。
5. 默认落点 `<工作区>/信息图/<主题>.html` 与同名 `.png`；同名存在时先 `ask_user`。

## 步骤

### 1. 提炼要点（3–7 个）
- 读完全文后写出：一句话标题（结论句，≤ 18 字）、一行副标题（口径/来源/时间）、3–7 个要点。每个要点 = 短标签（≤ 6 字）+ 数字或一句话（≤ 20 字）。
- 数字必须来自原文或数据，不能编造；单位、时间范围写清楚。超过 7 个要点就合并或拆成两张。
- 要点超过预期或信息不足时 `ask_user` 确认取舍。

### 2. 选模板与尺寸
| 内容形态 | 模板 | 要点数 |
|---|---|---|
| 几个关键数字 | 数字卡片（2×2 / 2×3 网格） | 3–6 |
| 先后顺序、操作方法 | 步骤流程（纵向编号，移动端友好） | 3–7 |
| 两到三个对象的差异 | 对比表（列对象、行维度，✓ ✗ 用符号不用纯色） | 2–3 列 × 3–6 行 |
| 时间上的演进 | 时间线（左轴右卡片） | 4–7 |
| 层级、递减、转化 | 金字塔 / 漏斗（SVG 内联绘制） | 3–5 层 |

常用尺寸（CSS 中固定 `body { width; min-height }`，截图前 `resize` 到同样宽高）：

| 用途 | 尺寸（px） | 说明 |
|---|---|---|
| 小红书 / 朋友圈竖图 | 1080×1350 | 默认；4:3 竖版，信息量大 |
| 公众号文中配图 | 1080×1440 或 1080×1920 | 长图可滚动，超过 1920 拆成多张 |
| 公众号封面 / 社交卡片 | 1200×628 | 横版，只放 1 个大数字或 3 个要点 |
| 微博 / 方图 | 1080×1080 | 2×2 数字卡片最合适 |
| 幻灯片插图 | 1600×900 | 配合 `web-deck-cn` 使用 |

### 3. 写 HTML
1. 用 `file_write` 写单文件 HTML。`<style>` 中先贴 `tokens.md` 的令牌 CSS，再加本图样式。
2. 选一个主色（黛蓝默认，节庆用朱砂，环保用松绿……），其余全部灰阶；数据系列用 `--s1…--s6`。
3. 版式：外边距 ≥ 64px（1080 宽），标题区占 15–20%，底部 60px 放来源与日期（`.source`）。
4. 图形全部 SVG 内联（箭头、漏斗、时间线圆点、图标），**不引任何外链图片和脚本**。需要装饰性配图时用 `generate_image`（提示词注明"无文字、留白、单色调、扁平插画"），保存到同目录后以 `<img src="./xxx.png">` 相对路径引用；**所有文字必须是 HTML 文本**，不要让模型把文字生成到图片里。
5. 字号：标题 44–56px/600，要点数字 56–72px/600 `tabular-nums`，要点标签 22px，正文 24–26px，来源 18px（1080 宽时，其他尺寸等比缩放）。
6. 对比度：正文 ≥ 4.5:1；浅色底为主，深色模式用 `prefers-color-scheme` 自动适配但截图用浅色。
7. 不要把 HTML 包在 Python/Shell 字符串里写出，直接写原样 HTML。

### 4. 截图导出 PNG
1. `shell_run`（`runInBackground: true`）：`python3 -m http.server 0 --directory <目录>`，用 `process_output` 读取端口。
2. `browser_automation`：`resize` 到目标尺寸（如 1080×1350）→ `open http://127.0.0.1:<端口>/<文件>.html` → `wait 800` → `screenshot`。
3. 保存：截图结果为临时图片时，用 `shell_run` 复制到 `<工作区>/信息图/<主题>.png`。若 `browser_automation` 的截图尺寸与目标不一致（设备像素比），改用 Chromium headless 一次性导出：
   ```bash
   "/Applications/Google Chrome.app/Contents/MacOS/Google Chrome" --headless=new --disable-gpu \
     --hide-scrollbars --window-size=1080,1350 --force-device-scale-factor=2 \
     --screenshot="<工作区>/信息图/<主题>.png" "http://127.0.0.1:<端口>/<文件>.html"
   ```
   `--force-device-scale-factor=2` 产出 2160×2700 的高清图，适合社媒上传。
4. 长图（高度超过视口）：先 `snapshot` 读取文档高度，再 `resize` 到该高度截图，或用上面的命令改 `--window-size`。

### 5. 自检
用 `view_image`（原图用 `detail: original`）核对：
- 中文无方块、无乱码；数字与单位之间有空格；标点全角。
- 文字无重叠、无截断、不溢出卡片；留白均匀。
- 只有一个主色；同一实体颜色一致；对比度达标。
- 标题是结论句；底部有来源与截至日期。
- 不合格修改后重截，最多三轮。结束后 `kill` 后台服务进程并关闭标签页。

## 注意事项 / 安全
- 数字和事实只来自用户提供的材料；引用网页时在底部注明来源与抓取日期。
- 输入含个人信息、内部数据时，先问是否脱敏；不要上传到在线作图服务。
- `generate_image` 的配图仅作装饰，不能承载信息；生成前告知用户会调用图像生成。
- 覆盖已有文件前 `ask_user`；文件名不含空格。
- 禁止"AI 味"：紫色渐变、玻璃拟态、每条要点一个 emoji、无意义图标网格。

## 如何确认完成
- 回复给出 HTML 与 PNG 的绝对路径，以及尺寸（如 1080×1350 @2x）。
- 一句话说明：采用的模板、主色、提炼出的要点数。
- 自检结论：文字清晰 / 无截断 / 来源已标注；若有信息取舍，列出被省略的要点。
