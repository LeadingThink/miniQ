# 评论分诊口径与回复模板

## 分诊决策顺序
1. 线程已被标记解决，或后续回复明确“不用改了/已处理” → **无需处理**。
2. 纯肯定、感谢、提问已被回答 → **无需处理**。
3. 两位审阅人对同一元素提出相反要求（如“标题改大”vs“标题太大了改小”），或所指内容在设计中找不到 → **需决策**。
4. 要求落在 API 不可做清单中 → **需手动**（可同时做一个 API 能做的近似改动，例如“换成更醒目的字体”可以先加粗放大，并在手动清单写明仍需换字体）。
5. 其余 → **可执行**。

## “积极理解”示例
| 评论 | 拟执行改动 |
|---|---|
| 标题太长 | 改写为 ≤ 12 字的短标题（给出新文案） |
| 这里数字不对，应该是 38% | `find_and_replace_text` 把原数字换成 38% |
| 字太小看不清 | 该文本 `format_text` 字号放大约 1.3 倍，确认不溢出 |
| 这张图不合适 | 需要新图：询问用户提供图片或在确认环节列为“需决策：请提供替换图” |
| Logo 太靠边 | `position_element` 向内移动到与正文左边距对齐 |
| 间距乱 | 用只读数据对齐元素 `left` 值；若涉及大量元素则列入手动 |
| 背景换成品牌蓝 | 需手动（API 不能改背景） |

## 定位评论所指元素
- 评论若带页码/锚点信息，直接用；否则根据评论引用的文字在 `get-design-content` 或事务 `richtexts` 中搜索。
- 仍无法确定 → 归为需决策，并在确认环节问用户。

## 回复评论模板（用评论原语言）
- 已修改：`已处理：将「旧文案」改为「新文案」。`
- 近似处理：`已先将标题加粗并放大；更换字体需在编辑器中手动完成，已列入待办。`
- 需手动：`此项需在 Canva 编辑器中手动调整（API 暂不支持更换背景色），已记录到待办清单。`
- 需决策：暂不回复，等用户决定后再回复。

## 回复前注意
- 回复会通知评论人，属于对外可见操作；已在一次性确认中告知用户“将回复评论”。
- 不在回复中暴露内部讨论或其他审阅人的个人信息。
